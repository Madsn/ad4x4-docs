    Round 1 (2026-04-01) — Previously Delivered¶

    #1 — Server-side filtering for user's trips — ✅ COMPLETE¶

    Both options implemented: - Option A: GET /api/trips/?registered=true / ?waitlisted=true filters on the trips list endpoint - Option B: Enriched GET /api/members/{id}/triphistory with 9 additional fields

    Recommendation: Use Option A for the "My Trips" portal. Use Option B for admin viewing of other members' trip history.

    API docs: docs/trips.md, docs/members.md

    #2 — Trailing-slash inconsistency — ❌ WON'T FIX¶

    Pattern is by design: Router-registered ViewSets require trailing slash; manual URL paths don't. Fully documented in docs/api-concepts.md.

    Round 2 (2026-04-02) — This Delivery¶

    #3 — Members endpoint ordering — ✅ COMPLETE¶

    Added OrderingFilter to MemberViewSet. The ordering parameter now works on GET /api/members/.

    Sortable fields: username, first_name, last_name, trip_count, level__numeric_level, date_joined, id, last_visited

    GET /api/members/?ordering=-trip_count          → most active first
GET /api/members/?ordering=username             → alphabetical
GET /api/members/?ordering=-date_joined         → newest first
GET /api/members/?ordering=-trip_count,username  → multi-field

    Default: id ascending (unchanged). Invalid fields silently ignored.

    API docs: docs/members.md

    #5 — paidMember filter — ✅ COMPLETE¶

    Added paid_member to member filter fields.

    GET /api/members/?paid_member=true   → only paid members
GET /api/members/?paid_member=false  → only unpaid members

    API docs: docs/members.md

    #6 — Unified advanced search for members — ✅ COMPLETE¶

    Added DRF SearchFilter to GET /api/members/. The search parameter performs case-insensitive partial matching across username, first_name, last_name, and email.

    GET /api/members/?search=hani                                     → text search
GET /api/members/?search=hani&paid_member=true&ordering=-trip_count → combined
GET /api/members/                                                  → all members (no search = browse)

    Key details: - Param name: search (not query) - No minimum character length - No additional permission required - The old /api/members/search endpoint is unchanged (backward compat) - The frontend can retire the dual-endpoint switching logic

    API docs: docs/members.md

    #7 — Last Visited tracking — ✅ COMPLETE¶

    Added last_visited field to the Member model with a throttled middleware that updates once per hour.

    Response field: lastVisited (camelCase, ISO 8601 datetime or null)

    Filters:

    GET /api/members/?last_visited__isnull=true         → never visited
GET /api/members/?last_visited_after=2026-03-01     → active since March 1
GET /api/members/?last_visited_before=2025-12-31    → inactive 90+ days
GET /api/members/?ordering=-last_visited            → most recently active first

    Initial state: All existing members have lastVisited: null. The field populates organically as members make authenticated requests.

    ⚠️ Migration required: Run python manage.py migrate after deployment. Migration: 0096_member_last_visited.py — adds nullable DateTimeField, no data migration needed.

    API docs: docs/members.md

    #8 — Trip search enhancements — ✅ COMPLETE¶

    Added three new parameters to GET /api/trips/search:

    Parameter Values Description
    approval_status P, A, R, C Filter by approval status. Invalid → 400.
    ordering start_time, -start_time, title, -title Sort order. Default: -start_time. Invalid → fallback to default.
    level_id integer (1–9) Filter by level database ID (resolves #10). 
    GET /api/trips/search?query=sand&approval_status=A           → approved only
GET /api/trips/search?query=sweihan&ordering=start_time       → oldest first
GET /api/trips/search?query=sand&level_id=4                   → Intermediate only
GET /api/trips/search?query=sand&approval_status=A&ordering=start_time&level_id=4  → combined

    Correction on meeting_point: The meeting_point filter already works by ID (see code). The original test returned 0 because combining with query=sweihan narrowed results to zero. The filter itself is functional.

    API docs: docs/trip-search.md

    #9 — Meeting points area backfill — ❌ DEFERRED¶

    The area field will be filled manually by users and admins when the app is operational. The field is already writable via PATCH /api/meetingpoints/{id}/. Automated backfill would be error-prone since many meeting point names don't clearly indicate which emirate they belong to.

    No code changes needed.

    #10 — Trip search level_id support — ✅ COMPLETE¶

    Resolved as part of #8. The level_id parameter on the search endpoint now filters by database ID, matching the list endpoint's level__id parameter. Both level (numericLevel) and level_id (database ID) coexist.

    API docs: docs/trip-search.md
