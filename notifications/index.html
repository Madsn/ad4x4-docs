    Notifications¶

    This document outlines the different types of push and email notifications sent by the backend.

    Registering for Push Notifications¶

    To receive push notifications, the client application must register the device's FCM token with the backend. This is done by making a POST request to the /api/device/fcm/ endpoint.

    POST /api/device/fcm/

    Request Body:

    {
    "registrationId": "your-fcm-token",
    "type": "ios"
}

    The type can be ios, android, or web.

    For more information on Firebase Cloud Messaging, please refer to the official documentation.

    Notification Types¶

    Trips¶

    • New Trip Notification: Sent when a new trip is created.
    • Trip Approval Notification: Sent when a trip is approved or rejected.
    • Accepted from Waitlist: Sent to a member when they are moved from the waitlist to the registered list for a trip.
    • Removed from Trip Registered List: Sent to a member when they are removed from the registered list for a trip.
    • Removed from Trip Waitlist: Sent to a member when they are removed from the waitlist for a trip.
    • New Trip Comment: Sent when a new comment is added to a trip. This is a push-only notification and is NOT stored in the notification log.

    Upgrade Requests¶

    • Upgrade Request Handled: Sent to a member when their upgrade request has been handled (approved or rejected).
    • Upgrade Request Created: Sent to the marshals when a new upgrade request is created.
    • Upgrade Request Reminder: A periodic reminder sent to the marshals about open upgrade requests.

    Club News¶

    • Club-Wide News: Sent to all members when a new club news item is published.

    Feedback¶

    • Feedback Notification: Sent to administrators when a member submits feedback via email/Telegram. This is not stored as a NotificationType log entry and does not appear in the notification history endpoint.

    NotificationType Enum Values¶

    The type field in the notification object will contain one of the following enum values:

    Value Description
    NEW_TRIP A new trip has been created.
    TRIP_APPR A trip has been approved or rejected.
    WAIT_ACC A user has been accepted from the waitlist.
    UPG_REQ_HAN An upgrade request has been handled.
    UPG_REQ_CRE A new upgrade request has been created.
    UPG_REQ_REM A reminder for an open upgrade request.
    CLUB_NEWS A new club news item has been published.
    REM_FROM_TRIP_REG A user has been removed from a trip's registered list.
    REM_FROM_TRIP_WAIT A user has been removed from a trip's waitlist.

    Note: Trip comment notifications are sent via push only and do not appear in the notification log. There is no NEW_TRIP_COMMENT enum value in NotificationType.

    Notification History¶

    A log of all notifications sent to a member is stored in the database. This allows the client application to display a history of notifications to the user.

    GET /api/notifications/

    Authentication: Required (Bearer token)

    The endpoint returns the 20 most recent notifications for the authenticated user, ordered by timestamp descending.

    Response Fields:

    Field Type Description
    id integer Unique notification ID
    title string Notification title
    body string Notification body text
    timestamp datetime When the notification was created
    type string Notification type enum value (see table above)
    relatedObjectId integer ID of the related object (e.g., trip ID, upgrade request ID). Can be null.
    relatedObjectType string Type of the related object (e.g., "trip", "upgrade_request"). Can be null.
    isRead boolean Whether the notification has been read

    Response Example:

    [
  {
    "id": 1,
    "title": "Trip Approved",
    "body": "Your trip 'Desert Safari' has been approved.",
    "timestamp": "2026-03-15T10:00:00",
    "type": "TRIP_APPR",
    "relatedObjectId": 456,
    "relatedObjectType": "trip",
    "isRead": false
  }
]

    Note: The endpoint returns a plain array of the 20 most recent notifications (no pagination wrapper). All field names use camelCase in the response.

    Marking Notifications as Read¶

    To mark one or more notifications as read, the client can make a POST request to the /api/notifications/mark-as-read/ endpoint.

    POST /api/notifications/mark-as-read/

    Request Body:

    {
    "notificationIds": [1, 2, 3]
}

    The notificationIds field should contain a list of notification IDs to be marked as read. The endpoint will return a 204 No Content response on success.

    Error Response (400 Bad Request):

    {
    "detail": "notification_ids must be provided."
}

    {
    "detail": "One or more notification IDs are invalid or do not belong to the user."
}

    Notification Settings¶

    Members can configure their notification preferences.

    GET /api/auth/profile/notificationsettings

    Note: This endpoint does NOT use a trailing slash.

    Authentication: Required (Bearer token)

    Response:

    {
  "clubNewsEnabledEmail": false,
  "clubNewsEnabledAppPush": true,
  "newTripAlertsEnabledEmail": false,
  "newTripAlertsEnabledAppPush": true,
  "newTripAlertsLevelFilter": [],
  "upgradeRequestReminderEmail": true,
  "tripChatEnabledAppPush": true,
  "lastUserActivity": "2026-03-15"
}

    Fields:

    Field Type Description
    clubNewsEnabledEmail boolean Receive club news via email
    clubNewsEnabledAppPush boolean Receive club news via push notification
    newTripAlertsEnabledEmail boolean Receive new trip alerts via email
    newTripAlertsEnabledAppPush boolean Receive new trip alerts via push notification
    newTripAlertsLevelFilter array Level IDs to filter trip alerts. Empty = all levels.
    upgradeRequestReminderEmail boolean Receive upgrade request reminders via email
    tripChatEnabledAppPush boolean Receive push notifications for trip chat messages
    lastUserActivity date Last user activity date (read-only, auto-updated). Note: This is a date-only field on the notification settings model. For datetime-precision activity tracking with filtering and ordering support, use the lastVisited field on the Member model — see Members.

    PUT/PATCH /api/auth/profile/notificationsettings

    Update notification settings. All fields except lastUserActivity are writable.

    Request Body (example partial update):

    {
  "clubNewsEnabledEmail": true,
  "newTripAlertsLevelFilter": [1, 2]
}

    Notification Purging¶

    To prevent the notification log from growing indefinitely, a periodic background task runs daily to purge old notifications. Any notification logs older than 60 days are automatically deleted from the database.
