    Notifications¶

    This document outlines the different types of push and email notifications sent by the backend.

    Registering for Push Notifications¶

    To receive push notifications, the client application must register the device's FCM token with the backend. This is done by making a POST request to the /api/device/fcm/ endpoint.

    POST /api/device/fcm/

    Request Body:

    {
    "registration_id": "your-fcm-token",
    "type": "ios"
}

    The type can be ios, android, or web.

    For more information on Firebase Cloud Messaging, please refer to the official documentation.

    Notification Types¶

    Trips¶

    • New Trip Notification: Sent when a new trip is created.
    • Trip Approval Notification: Sent when a trip is approved or rejected.
    • Accepted from Waitlist: Sent to a member when they are moved from the waitlist to the registered list for a trip.
    • Removed from Trip Registered List: Sent to a member when they are removed from the registered list for a trip.
    • Removed from Trip Waitlist: Sent to a member when they are removed from the waitlist for a trip.
    • New Trip Comment: Sent when a new comment is added to a trip. This is used for the real-time chat feature.

    Upgrade Requests¶

    • Upgrade Request Handled: Sent to a member when their upgrade request has been handled (approved or rejected).
    • Upgrade Request Created: Sent to the marshals when a new upgrade request is created.
    • Upgrade Request Reminder: A periodic reminder sent to the marshals about open upgrade requests.

    Club News¶

    • Club-Wide News: Sent to all members when a new club news item is published.

    Feedback¶

    • Feedback Notification: Sent to the administrators when a member submits feedback.

    NotificationType Enum Values¶

    The type field in the notification object will contain one of the following enum values:

    Value Description
    NEW_TRIP A new trip has been created.
    TRIP_APPR A trip has been approved or rejected.
    WAIT_ACC A user has been accepted from the waitlist.
    UPG_REQ_HAN An upgrade request has been handled.
    UPG_REQ_CRE A new upgrade request has been created.
    UPG_REQ_REM A reminder for an open upgrade request.
    CLUB_NEWS A new club news item has been published.
    REM_FROM_TRIP_REG A user has been removed from a trip's registered list.
    REM_FROM_TRIP_WAIT A user has been removed from a trip's waitlist.

    Notification History¶

    A log of all notifications sent to a member is stored in the database. This allows the client application to display a history of notifications to the user.

    GET /api/notifications/

    The endpoint returns a paginated list of the 20 most recent notifications for the authenticated user. Each notification object in the response now includes an is_read boolean field, which indicates whether the notification has been read by the user.

    Marking Notifications as Read¶

    To mark one or more notifications as read, the client can make a POST request to the /api/notifications/mark_as_read/ endpoint.

    POST /api/notifications/mark_as_read/

    Request Body:

    {
    "notification_ids": [1, 2, 3]
}

    The notification_ids field should contain a list of notification IDs to be marked as read. The endpoint will return a 204 No Content response on success.

    Notification Purging¶

    To prevent the notification log from growing indefinitely, a periodic background task runs daily to purge old notifications. Any notification logs older than 60 days are automatically deleted from the database.
