    API Concepts¶

    This document covers high-level concepts for interacting with the AD4x4 API.

    Time Zone¶

    All dates and times in the API use Asia/Dubai time zone (UTC+4) with no daylight saving time.

    Examples: - 2024-12-15T07:00:00+04:00 - December 15, 2024 at 7:00 AM Dubai time - 2024-12-14T18:00:00+04:00 - December 14, 2024 at 6:00 PM Dubai time

    Important: The USE_TZ setting is False, so times are stored and returned as-is in Dubai time without UTC conversion.

    Authentication¶

    The API uses JWT (JSON Web Token) authentication. To authenticate:

    1. Obtain Token: POST to /api/token/ with username and password
    2. Use Token: Include in Authorization header as Bearer <token>
    3. Refresh Token: POST to /api/token/refresh/ with refresh token

    Authentication Header Format¶

    Authorization: Bearer <your_jwt_token>

    Token Endpoints¶

    Obtain Token Pair¶

    • Endpoint: POST /api/token/
    • Body: json { "username": "your_username", "password": "your_password" }
    • Response: json { "access": "eyJ0eXAiOiJKV1QiLCJhbGc...", "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc..." }

    Refresh Token¶

    • Endpoint: POST /api/token/refresh/
    • Body: json { "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc..." }
    • Response: json { "access": "eyJ0eXAiOiJKV1QiLCJhbGc..." }

    Response Format¶

    Most endpoints return responses in the following formats. Note that the message field can be either a string or an object depending on the endpoint.

    Success Response (Unified)¶

    When message is a string:

    {
  "success": true,
  "message": "operation_successful"
}

    When message is an object (data responses):

    {
  "success": true,
  "message": {
    "id": 456,
    "title": "Weekend Trip",
    ...
  }
}

    Error Response (Unified)¶

    When message is a string:

    {
  "success": false,
  "message": "error_description"
}

    When message is an object (validation errors):

    {
  "success": false,
  "message": {
    "field_name": [
      "This field is required."
    ]
  }
}

    List Response (Paginated)¶

    {
  "count": 100,
  "next": "http://api.example.org/api/items/?page=3",
  "previous": "http://api.example.org/api/items/?page=1",
  "results": []
}

    Error Handling¶

    The API uses standard HTTP status codes and returns detailed error messages.

    Common Error Responses¶

    400 Bad Request¶

    {
  "success": false,
  "message": {
    "field_name": [
      "This field is required."
    ],
    "another_field": [
      "Invalid value."
    ]
  }
}

    401 Unauthorized¶

    {
  "detail": "Authentication credentials were not provided."
}

    or

    {
  "detail": "Given token not valid for any token type"
}

    403 Forbidden¶

    {
  "success": false,
  "message": "no_permission_to_perform_action"
}

    404 Not Found¶

    {
  "detail": "Not found."
}

    422 Unprocessable Entity¶

    {
  "success": false,
  "message": "waitlist_enforced_globally"
}

    500 Internal Server Error¶

    {
  "error": "An unexpected error occurred. Please try again later."
}

    File Uploads¶

    Endpoints that accept file uploads (images, track files, etc.) use multipart/form-data encoding.

    Example: Upload Trip Image¶

    curl -X PATCH http://localhost:8000/api/trips/456/ \
  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -F "image=@/path/to/image.jpg" \
  -F "title=Updated Trip Title"

    Supported File Types¶

    • Images: JPEG, PNG, GIF
    • Track Files: GPX, KML
    • Documents: PDF (for certain endpoints)

    File Size Limits¶

    • Profile avatars: 5MB
    • Car images: 5MB
    • Trip images: 10MB
    • Track files: 2MB

    Best Practices¶

    1. Always use HTTPS in production
    2. Store JWT tokens securely (not in localStorage for web apps)
    3. Refresh tokens before they expire
    4. Handle token expiration gracefully
    5. Use pagination for large datasets
    6. Implement proper error handling
    7. Validate data on the client side before sending
    8. Use appropriate HTTP methods (GET, POST, PUT, PATCH, DELETE)
    9. Include proper Content-Type headers
    10. Test with the Swagger UI at /docs/swagger-ui/

    Troubleshooting¶

    Authentication Issues¶

    "Given token not valid for any token type"¶

    Cause: Token is expired, invalid, or malformed

    Solutions: 1. Refresh the token using /api/token/refresh/ 2. Re-authenticate with username and password 3. Check token format (should start with eyJ...)

    "Authentication credentials were not provided"¶

    Cause: Missing or malformed Authorization header

    Solutions: 1. Ensure header is present: Authorization: Bearer <token> 2. Check for typos in "Bearer" (case-sensitive) 3. Verify token is not empty or None

    Permission Errors¶

    "nopermissiontoperformaction"¶

    Cause: User lacks required permission for the action

    Solutions: 1. Check user has correct group membership 2. Verify permission exists in PermissionMatrix 3. Contact administrator for elevated permissions

    Field Validation Errors¶

    Field shows "This field is required" but value is provided¶

    Causes: 1. Wrong field name (camelCase vs snake_case mismatch) 2. Field not expected by this endpoint/method 3. Type mismatch (string vs number)

    Solutions: 1. Use camelCase for API requests (e.g., startTime not start_time) 2. Check Swagger documentation for accepted fields 3. Verify data type matches expected format

    503 Service Unavailable¶

    Cause: Maintenance mode is enabled

    Solutions: 1. Wait and retry after a few minutes 2. Check Club News for maintenance announcements 3. See Maintenance Mode

    Pagination Issues¶

    "count": 0 with no results¶

    Causes: 1. No data matching filter criteria 2. Page number exceeds available pages 3. Authentication required for filtered results

    Solutions: 1. Remove filters to see all data 2. Request page 1 if using page numbers 3. Verify authentication token

    Next/Previous URLs are null¶

    Null next: You are on the last page Null previous: You are on the first page

    Rate Limiting¶

    Requests returning 429 Too Many Requests¶

    Cause: Exceeded rate limit (100 requests/minute per IP)

    Solutions: 1. Implement exponential backoff 2. Reduce request frequency 3. Cache responses locally

    See Rate Limiting for details.

    Date/Time Issues¶

    Trip times appearing incorrect¶

    Cause: Client not parsing timezone correctly

    Solutions: 1. All API times are in Asia/Dubai (UTC+4) 2. Parse with timezone awareness 3. Examples: 2024-12-15T07:00:00+04:00

    File Upload Issues¶

    "Request is not a multipart request"¶

    Cause: Wrong Content-Type for file upload

    Solutions: 1. Use multipart/form-data not application/json 2. Do not JSON-encode the body 3. Use appropriate HTTP client settings

    File too large (413 Payload Too Large)¶

    Cause: File exceeds size limit

    Solutions: 1. Compress images before upload 2. Stay within limits: - Profile avatars: 5MB - Car images: 5MB - Trip images: 10MB - Track files: 2MB

    Common HTTP Status Codes¶

    Code Meaning Common Causes
    200 OK Successful request
    201 Created Resource successfully created
    400 Bad Request Invalid data, validation errors
    401 Unauthorized Missing or invalid token
    403 Forbidden Permission denied
    404 Not Found Resource doesn't exist
    422 Unprocessable Business rule violation
    429 Too Many Requests Rate limit exceeded
    500 Internal Server Error Server error, check logs
    503 Service Unavailable Maintenance mode

    Getting Help¶

    1. Check Swagger UI at /docs/swagger-ui/ for interactive testing
    2. Review error messages in response body
    3. Check server logs for detailed error information
    4. Contact support via the feedback system
