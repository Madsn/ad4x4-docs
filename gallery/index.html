    Gallery System Configuration¶

    The gallery system provides media management for trip photos. Galleries are synced with an external Gallery API, and all sync operations happen asynchronously via background tasks.

    Architecture¶

    Trip Approved
    ↓
Background Task: create_gallery_for_trip_task
    ↓
GalleryWebhookService.create_gallery_for_trip()
    ↓
External Gallery API
    ↓
Response stored in Trip.gallery_id

    Configuration Fields¶

    Setting Type Description
    gallery_api_url String Base URL for the external Gallery API
    gallery_api_timeout Integer Timeout in seconds for API calls (default: 10)
    enable_gallery_system Boolean Master switch to enable/disable all gallery features
    auto_create_trip_gallery Boolean Auto-create gallery when trip is approved
    allow_manual_gallery_creation Boolean Allow clients to show manual creation UI

    Gallery ID Storage¶

    When a gallery is successfully created for a trip, the external gallery ID is stored in:

    trip.gallery_id = "<external_gallery_id>"
trip.save(update_fields=['gallery_id'])

    This allows the system to reference the gallery for future updates.

    Background Tasks¶

    Create Gallery¶

    Trigger: Trip approval Task: create_gallery_for_trip_task(trip_id) Retry Policy: 6 retries, 1 hour delay between retries

    Update Gallery¶

    Trigger: Trip details change Task: update_gallery_for_trip_task(trip_id) Retry Policy: 6 retries, 1 hour delay between retries

    Delete Gallery¶

    Trigger: Trip soft-delete Task: delete_gallery_for_trip_task(trip_id) Retry Policy: 3 retries, 1 hour delay between retries

    Restore Gallery¶

    Trigger: Trip restoration Task: restore_gallery_for_trip_task(trip_id) Retry Policy: 3 retries, 1 hour delay between retries

    Error Handling¶

    Retry Logic¶

    All gallery tasks implement exponential backoff with the following pattern:

    1. Initial attempt
    2. Retry after 1 hour
    3. Retry after 2 hours
    4. Retry after 4 hours
    5. ... up to configured retries

    After all retries are exhausted, the task stops and logs an error. Manual intervention may be required.

    Logging¶

    Gallery operations log to the ad4x4-worker logger:

    # Success
logger.info(f"Gallery ID {gallery_id} saved to trip {trip.id}")

# Failure
logger.warning(f"Gallery creation failed for trip {trip.id}, will retry")

# Error
logger.error(f"Trip {trip_id} not found when creating gallery")

    Testing Gallery Integration¶

    Manual Test¶

    from api.services.gallery_webhook import GalleryWebhookService
from api.models import Trip

trip = Trip.objects.first()
gallery_id = GalleryWebhookService.create_gallery_for_trip(trip)
print(f"Created gallery: {gallery_id}")

    Disable for Testing¶

    Set enable_gallery_system = False in Global Settings to prevent API calls during testing.

    Client-Side Integration¶

    Displaying Galleries¶

    1. Check if trip.gallery_id exists
    2. Construct gallery URL using the external Gallery API base URL
    3. Display gallery iframe or link

    Manual Creation Flag¶

    Respect allow_manual_gallery_creation to show/hide "Create Gallery" buttons in the UI.

    Troubleshooting¶

    Gallery Not Created¶

    Symptom: Trip approved but no gallery_id on trip Causes: - Gallery system disabled (enable_gallery_system = False) - External API unreachable - Task failed all retries Fix: Check logs, verify settings, manually trigger gallery creation

    Gallery Sync Failures¶

    Symptom: Repeated failures in logs Causes: - Invalid API credentials - Network issues - External API down Fix: Verify credentials, check external API status, check Huey consumer running
