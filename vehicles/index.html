    Vehicles¶

    This document outlines the API endpoints for managing member vehicles. Members can now register multiple vehicles, with a configurable limit set in global settings.

    Vehicle List¶

    Retrieve all vehicles for the authenticated user.

    GET /api/vehicles/

    Authentication: Required (Bearer token)

    Query Parameters: - page - Page number (default: 1) - page_size - Number of results per page (default: 20, max: 500) - include_archived - Set to true to include archived vehicles in the list

    Success Response:

    {
  "count": 2,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1,
      "name": "My Land Cruiser",
      "brand": "TO",
      "brandDisplay": "Toyota",
      "model": "Land Cruiser",
      "year": 2020,
      "color": "White",
      "isPrimary": true,
      "archived": false,
      "archivedAt": null,
      "tripCount": 12
    },
    {
      "id": 2,
      "name": "Nissan Patrol",
      "brand": "NI",
      "brandDisplay": "Nissan",
      "model": "Patrol",
      "year": 2019,
      "color": "Black",
      "isPrimary": false,
      "archived": false,
      "archivedAt": null,
      "tripCount": 4
    }
  ]
}

    Create Vehicle¶

    Create a new vehicle for the authenticated user.

    POST /api/vehicles/

    Authentication: Required (Bearer token)

    Request Body:

    {
  "name": "My Land Cruiser",
  "brand": "TO",
  "model": "Land Cruiser",
  "year": 2020,
  "color": "White",
  "isPrimary": true
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | name | string | No | User-friendly name for the vehicle | | brand | string | Yes | 2-letter car brand code (e.g., "TO" for Toyota, "NI" for Nissan). See Car Brand Choices for all valid codes. | | model | string | No | Vehicle model | | year | integer | No | Year of manufacture | | color | string | No | Vehicle color | | image | file | No | Vehicle image (multipart/form-data) | | isPrimary | boolean | No | Set as primary vehicle (default: false) |

    Validation: - Maximum number of vehicles is limited by vehicle_limit_per_member setting (default: 3) - brand must be a valid CarBrand choice

    Success Response:

    {
  "success": true,
  "message": {
    "id": 1,
    "member": 123,
    "name": "My Land Cruiser",
    "brand": "TO",
    "brandDisplay": "Toyota",
    "model": "Land Cruiser",
    "year": 2020,
    "color": "White",
    "image": null,
    "isPrimary": true,
    "archived": false,
    "archivedAt": null,
    "tripCount": 12,
    "createdAt": "2026-03-05T00:00:00.000Z",
    "updatedAt": "2026-03-05T00:00:00.000Z"
  }
}

    Error Response (limit reached):

    {
  "success": false,
  "message": "Maximum number of vehicles (3) reached. Please delete an existing vehicle first."
}

    Get Vehicle¶

    Get details of a specific vehicle.

    GET /api/vehicles/{id}/

    Authentication: Required (Bearer token)

    Note: Archived vehicles are returned normally by the detail endpoint.

    Success Response:

    {
  "success": true,
  "message": {
    "id": 1,
    "member": 123,
    "name": "My Land Cruiser",
    "brand": "TO",
    "brandDisplay": "Toyota",
    "model": "Land Cruiser",
    "year": 2020,
    "color": "White",
    "image": "/media/vehicles/2026/03/vehicle_abc123.jpg",
    "isPrimary": true,
    "archived": false,
    "archivedAt": null,
    "tripCount": 12,
    "createdAt": "2026-03-05T00:00:00.000Z",
    "updatedAt": "2026-03-05T00:00:00.000Z"
  }
}

    Update Vehicle¶

    Update a vehicle's details.

    PATCH /api/vehicles/{id}/

    Authentication: Required (Bearer token)

    Request Body:

    {
  "year": 2021,
  "color": "Silver"
}

    Note: Users can only update their own vehicles.

    Archive Vehicle¶

    Archive a vehicle to hide it from the default active list while preserving trip history.

    POST /api/vehicles/{id}/archive/

    Authentication: Required (Bearer token)

    Notes: - Idempotent. Archiving an already archived vehicle returns 200 without changing archivedAt. - If the archived vehicle was primary, the most recently created non-archived vehicle is promoted to primary. - Admin users can archive any vehicle; regular members can only archive their own.

    Unarchive Vehicle¶

    Restore an archived vehicle.

    POST /api/vehicles/{id}/unarchive/

    Authentication: Required (Bearer token)

    Notes: - Idempotent. Unarchiving an already active vehicle returns 200. - Unarchive does not make the vehicle primary automatically.

    Delete Vehicle¶

    Delete a vehicle.

    DELETE /api/vehicles/{id}/

    Authentication: Required (Bearer token)

    Note: If the deleted vehicle was the primary vehicle, the most recently created remaining active vehicle will be automatically set as primary.

    Success Response: 204 No Content

    Error Response (vehicle still in use):

    {
  "success": false,
  "message": "vehicle_in_use_cannot_delete",
  "detail": "Vehicle is still referenced by related records and cannot be deleted.",
  "referencedCount": 74
}

    This response returns 409 Conflict when Django raises ProtectedError while deleting the vehicle. The referencedCount field is best effort and may be omitted if the backend cannot determine it.

    Set Primary Vehicle¶

    Set a vehicle as the primary vehicle. Only one vehicle can be primary at a time.

    POST /api/vehicles/{id}/set_primary/

    Authentication: Required (Bearer token)

    Success Response:

    {
  "success": true,
  "message": {
    "id": 2,
    "member": 123,
    "name": "Nissan Patrol",
    "brand": "NI",
    "brandDisplay": "Nissan",
    "model": "Patrol",
    "year": 2019,
    "color": "Black",
    "isPrimary": true,
    ...
  }
}

    Note: If the vehicle is archived, set_primary will restore it to active first and then mark it primary.

    Car Brand Choices¶

    Get available car brand choices.

    GET /api/choices/carbrand

    Brand codes are 2-letter codes, not full brand names. Common examples:

    Code Brand
    TO Toyota
    NI Nissan
    LR Land Rover
    JE Jeep
    MT Mitsubishi
    FO Ford
    ME Mercedes-Benz
    BM BMW

    Use the /api/choices/carbrand endpoint to get the full list of valid codes.

    Global Settings¶

    The vehicle limit per member can be configured in global settings:

    • vehicle_limit_per_member - Maximum number of vehicles a member can register (default: 3)
    • Archived vehicles do not count toward the limit.

    Trip Registration with Vehicle¶

    When registering for a trip, members must select which vehicle they will use. The vehicle information is stored with the trip registration and displayed in the trip details and export.

    Endpoints That Support Vehicle Registration¶

    The following endpoints support optional vehicle_id parameter for vehicle association:

    Endpoint Description Vehicle Source
    POST /api/trips/ Create trip (lead registered) Optional; defaults to lead's primary
    POST /api/trips/{id}/register/ User registers for trip Required for regular users; optional for staff
    POST /api/trips/{id}/forceregister Staff force-register a member Optional; defaults to member's primary
    POST /api/trips/{id}/approve/ Approve trip (approver registered) Optional; defaults to approver's primary
    POST /api/trips/{id}/waitlist Join waitlist Optional; stored with waitlist entry
    POST /api/trips/{id}/addfromwaitlist Move member from waitlist to registered Uses vehicle from waitlist entry

    Register for Trip¶

    POST /api/trips/{tripId}/register

    Authentication: Required (Bearer token)

    Request Body:

    {
  "vehicleId": 123
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | vehicleId | integer | Yes* | ID of the vehicle to register with | | confirmOverlap | boolean | No | Set to true only when retrying after a trip-overlap warning |

    *Required for regular users. Users with edit_trip_registrations permission (staff/marshals) can omit - defaults to their primary vehicle.

    Validation: - User must have at least one vehicle registered (unless staff with permission) - Vehicle must belong to the user - Vehicle is required (returns 400 error if not provided)

    Success Response:

    {
  "success": true,
  "message": "trip_registered",
  "trip": { "...": "updated trip object" }
}

    Overlap Warning Response:

    If the member has an approved or pending overlapping trip where they are registered or primary lead, registration returns 409 Conflict and does not mutate state:

    {
  "success": false,
  "message": "trip_overlap_warning",
  "warnings": [
    {
      "code": "trip_overlap",
      "conflicts": [
        {
          "id": 123,
          "title": "Existing Trip",
          "startTime": "2026-05-20T06:00:00Z",
          "endTime": "2026-05-20T12:00:00Z",
          "role": "registered"
        }
      ]
    }
  ]
}

    Retry with the same vehicleId plus confirmOverlap: true to proceed after user confirmation.

    Error Responses:

    No vehicles registered:

    {
  "success": false,
  "message": "vehicle_required"
}

    Vehicle not found or doesn't belong to user:

    {
  "success": false,
  "message": "vehicle_not_found"
}

    Create Trip (Lead Registration)¶

    When a trip is created, the lead is automatically registered to the trip.

    POST /api/trips/

    Authentication: Required (Bearer token)

    Request Body:

    {
  "title": "Desert Trip",
  "lead": 123,
  "level": 1,
  "start_time": "2026-03-15T08:00:00Z",
  "end_time": "2026-03-15T18:00:00Z",
  "cut_off": "2026-03-14T20:00:00Z",
  "capacity": 10,
  "vehicle_id": 456
}

    Vehicle Field: | Field | Type | Required | Description | |-------|------|----------|-------------| | vehicle_id | integer | No | ID of the vehicle the lead will use. Defaults to lead's primary vehicle if not specified. |

    Force Register for Trip¶

    Staff can force-register a member for a trip, bypassing level requirements.

    POST /api/trips/{tripId}/forceregister

    Note: This endpoint does NOT use a hyphen or trailing slash.

    Authentication: Required (Bearer token)

    Request Body:

    {
  "member": 456,
  "vehicle_id": 789
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | member | integer | Yes | ID of the member to register | | vehicle_id | integer | No | ID of the vehicle. Defaults to member's primary vehicle if not specified. |

    Approve Trip¶

    When a marshal approves a trip, they are automatically registered as a deputy lead.

    POST /api/trips/{tripId}/approve/

    Authentication: Required (Bearer token)

    Request Body:

    {
  "vehicle_id": 123
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | vehicle_id | integer | No | ID of the vehicle the approver will use. Defaults to their primary vehicle if not specified. |

    Join Waitlist¶

    Members can join a trip waitlist and optionally specify their vehicle.

    POST /api/trips/{tripId}/waitlist

    Note: This endpoint does NOT use a trailing slash.

    Authentication: Required (Bearer token)

    Request Body:

    {
  "vehicle_id": 123
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | vehicle_id | integer | No | ID of the vehicle. Defaults to user's primary vehicle if not specified. |

    The vehicle is stored with the waitlist entry and will be used when the member is moved from waitlist to registered.

    Accept from Waitlist¶

    When a lead/marshal moves a member from waitlist to registered, the vehicle stored with the waitlist entry is used.

    POST /api/trips/{tripId}/addfromwaitlist

    Note: This endpoint does NOT use a trailing slash.

    Authentication: Required (Bearer token)

    Request Body:

    {
  "member": 456
}

    Fields: | Field | Type | Required | Description | |-------|------|----------|-------------| | member | integer | Yes | ID of the member to move from waitlist |

    The vehicle is automatically taken from the waitlist entry. If no vehicle was specified when joining the waitlist, the member's primary vehicle is used.

    Trip Export¶

    When exporting trip registrants, the CSV includes the selected vehicle:

    • Column: car_brand_model_color - Contains the vehicle brand, model, and color from the selected vehicle

    See Global Settings for more details.
