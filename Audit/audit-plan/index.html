    AD4x4 Backend — Audit Plan¶

    12-step audit plan. Each step names: scope, tools, outputs, acceptance criteria.

    Raw outputs land in raw/NN-<slug>.md. Findings from each step feed the consolidated audit-report.md.

    Step 1 — Django system checks (baseline)¶

    • Scope: Django's own validation of the project configuration
    • Tools: mcp__django-ai-boost__run_check, python manage.py check --deploy via bash
    • Output: raw/01-system-check.md
    • Acceptance: All check messages captured, each tagged severity + confidence high. Production-only deploy-check warnings flagged even if dev passes.

    Step 2 — Endpoint drift¶

    • Scope: Are CLAUDE.md §6, schema.yml, and actual URL patterns aligned?
    • Tools: mcp__django-ai-boost__list_urls, Read on ad4x4/urls.py, schema.yml, CLAUDE.md
    • Output: raw/02-endpoint-drift.md with three lists: (a) in URL conf but undocumented, (b) documented but missing, (c) present but with wrong method/path in docs
    • Acceptance: Every /api/* route in URL conf accounted for. Schema regeneration recommended if endpoints exist with no @extend_schema.

    Step 3 — Model & schema drift¶

    • Scope: Do CLAUDE.md §5, ORM model definitions, and DB schema agree?
    • Tools: mcp__django-ai-boost__list_models, mcp__django-ai-boost__database_schema, Read on CLAUDE.md, api/models/*.py
    • Output: raw/03-model-schema.md flagging: (a) FK columns without db_index=True that are filtered/joined in views, (b) ORM db_index=True not reflected in DB, (c) documented fields that don't match reality, (d) fields not in docs
    • Acceptance: Every model in CLAUDE.md §5 verified. Index coverage assessed on all models with FK/filter-heavy usage.

    Step 4 — Migration health¶

    • Scope: Applied vs unapplied state; migration hygiene
    • Tools: mcp__django-ai-boost__list_migrations, Bash find api/migrations -name "*.py"
    • Output: raw/04-migrations.md with unapplied list, total count vs CLAUDE.md §3 (claims 98), squash candidates (long sequences of no-op schema changes)
    • Acceptance: No silent pending migrations. Count matches docs.

    Step 5 — Settings & middleware audit¶

    • Scope: Production readiness, middleware order, secure defaults
    • Tools: mcp__django-ai-boost__application_info, mcp__django-ai-boost__get_setting on non-secret keys, Read on ad4x4/settings.py
    • Output: raw/05-settings-middleware.md recording: DEBUG, ALLOWED_HOSTS, SECURE_*, SESSION_*, CSRF_*, CORS_*, middleware order, DB engine, cache backend, USE_TZ, TIME_ZONE
    • Acceptance: Middleware order sane (CORS before Common, Whitenoise before custom media). No get_setting call ever resolves a secret value.

    Step 6 — Code review (parallel)¶

    • Scope: Recently stable + high-traffic Python modules
    • Tools: django-reviewer:django-reviewer agent × N, Opus model
    • Targets (one agent each):
    • api/views/views_trips.py
    • api/views/views_members.py
    • api/views/views_upgraderequests.py
    • api/views/views_logbook.py
    • api/views/views_auth.py
    • api/services/ (aggregate across tripregistration, notification, upgradeeligibility, autoupgrade, gallerywebhook)
    • api/permissions.py
    • api/background.py (passes to step 8 also)
    • Output: raw/06-code-review.md — aggregated findings by file, each with file:line and severity
    • Acceptance: Every target file reviewed. Findings non-overlapping with step 10 (security) — overlaps merged in the final report.

    Step 7 — Performance probes¶

    • Scope: Index hit-rate signals, N+1 hotspots, orphan data
    • Tools: mcp__django-ai-boost__query_model (aggregates only), mcp__django-ai-boost__database_schema for index visibility, Grep for select_related/prefetch_related patterns
    • Output: raw/07-performance-probes.md — per-hotspot finding: evidence + recommendation
    • Acceptance: At least: member lookup paths, trip registration joins, logbook skill references, notification log retention assessed. No raw PII rows captured.

    Step 8 — Async task audit¶

    • Scope: api/background.py — Huey task design, retries, idempotency
    • Tools: Opus general-purpose agent with django-celery-expert skill patterns as reference (Huey semantics close enough)
    • Output: raw/08-async-tasks.md — per-task: idempotency, retry strategy, transaction boundary, error path, observability
    • Acceptance: All ~15 tasks listed in CLAUDE.md §10 reviewed. Periodic tasks reviewed for drift.

    Step 9 — Architecture sweep¶

    • Scope: Blast-radius hotspots, coupling, god-nodes
    • Tools: Opus general-purpose agent reading graphify-out/GRAPH_REPORT.md, then verifying top-fan-in nodes against source
    • Output: raw/09-architecture.md — top 10 highest-risk nodes with verified edges, refactor suggestions if any, false-positive Graphify edges noted
    • Acceptance: Findings tagged medium where Graphify-inferred unless verified in source.

    Step 10 — Security pass¶

    • Scope: Pending-branch changes + well-known Django pitfalls
    • Tools: built-in security-review skill, cross-ref to CLAUDE.md §7 (JWT), §8 (permissions), §15 (gotchas)
    • Output: raw/10-security.md
    • Acceptance: Every finding has remediation and file:line. Known-false-positives filtered.

    Step 11 — Dependency audit¶

    • Scope: CVEs in requirements.txt and requirements-dev.txt
    • Tools: pip-audit (installed into .venv if missing)
    • Output: raw/11-dependencies.md — vulnerable packages, CVE IDs, fix versions
    • Acceptance: Both requirement files scanned. Zero-finding result explicitly stated.

    Step 12 — Documentation drift¶

    • Scope: CLAUDE.md (and mirrored SKILL.md) vs reality
    • Tools: cross-ref outputs of steps 2, 3, 4, 5, 8, 10
    • Output: raw/12-doc-drift.md — sections of CLAUDE.md requiring update, with suggested edits
    • Acceptance: Every drift finding cites both the doc line and the source-of-truth file:line.

    Consolidation¶

    After all 12 steps, the consolidated audit-report.md is assembled by:

    1. Merging findings from all raw/*.md
    2. Deduplicating overlaps (e.g., a finding that appears in both step 6 and step 10 merges under whichever is more specific)
    3. Sorting by severity, then confidence, then step
    4. Assigning an owner hint (models / views / services / infra / docs) to each finding
    5. Producing a Top 10 highest-impact fixes list at the top

    Parallelism schedule¶

    • Sequential (in-session): Steps 1, 2, 3, 4, 5, 7, 10, 11, 12
    • Parallel batch A (~7 Opus agents): Step 6 code reviewers, fired simultaneously
    • Parallel batch B (~2 Opus agents): Step 8 (async task deep-dive) + Step 9 (architecture sweep), fired simultaneously

    Total estimated subagent count: ~9. Plus ~30–50 MCP tool calls in-session.
