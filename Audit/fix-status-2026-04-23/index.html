    Scope of 44e345d¶

    Headline verdict¶

    Major, high-quality tranche. ~17 additional findings resolved (verified in source), bringing total to ~30 of 105 F-findings resolved.     Newly resolved findings (verified in source for 44e345d)¶

    F-03 — Django + 8 dep CVEs¶

    • Status: RESOLVED
    • Evidence: requirements.txt now pins:
    • Django==6.0.4 (was 6.0.1) — closes 13 Django CVEs including SQL-injection in QuerySet.order_by()
    • cryptography==46.0.7 (was 46.0.4) — closes buffer-overflow in Hash.update()
    • PyJWT==2.12.0 (was 2.11.0) — closes crit header bypass
    • pillow==12.2.0 (was 12.1.0) — closes PSD out-of-bounds write + FITS decomp bomb
    • requests==2.33.0, pyasn1==0.6.3, Pygments==2.20.0, python-dotenv==1.2.2
    • Confirmation: Co-dev's pip-audit reports "No known vulnerabilities found".
    • Strength of fix: Clean batch bump, zero API surface change.

    F-04 — transaction.on_commit in signals¶

    • Status: RESOLVED
    • Evidence: api/signals.py — 8 transaction.on_commit call sites now cover all 6 previously-direct enqueue sites (upgrade request, 5 gallery tasks, trip comment, club news task). No direct send_*_notification(instance) or *_task(instance) calls remain.
    • Tests: tests/test_signal_commit_boundaries.py — new file asserts deferral by forcing rollback + mock_send.assert_not_called().

    F-07 — Vehicle set_primary endpoint wiring¶

    • Status: RESOLVED
    • Evidence: api/views/views_vehicle.py:130 — @action(detail=True, methods=['post']) decorator. Removed manual as_view() from ad4x4/urls.py. Schema generation issue from raw/01-system-check.md closes as side effect.

    F-12 — Member directory PII exposure (view-level gate)¶

    • Status: RESOLVED
    • Evidence: api/views/views_member.py:142-146 — MemberViewSet.get_permissions() returns HasSearchMembersPermission for list/retrieve, IsEditingOwnProfileOrAdmin for update/partial_update, DenyAll otherwise. Previously was IsAuthenticatedOrReadOnly (any authenticated user could enumerate).

    F-13 — Vehicle limit TOCTOU¶

    • Status: RESOLVED
    • Evidence: api/views/views_vehicle.py:73, 112 — request.user.__class__.objects.select_for_update().get(pk=request.user.pk) before reading vehicle_limit and counting existing vehicles. select_for_update on the user row serializes concurrent POSTs.

    F-15 — Permission classes raising 500 on unknown IDs¶

    • Status: RESOLVED
    • Evidence: api/permissions.py — 6 DoesNotExist sites (UpgradeRequest, Trip) now return False cleanly. No more unhandled exceptions on crafted URL params.

    F-17 — Logbook skill reference history preservation¶

    • Status: RESOLVED
    • Evidence:
    • Migration api/migrations/0099_logbookskillreference_unique.py — adds UniqueConstraint(fields=('member', 'trip', 'logbook_skill')) and dedups existing duplicates via RunPython.
    • api/views/views_logbook.py:39 — now uses LogbookSkillReference.objects.update_or_create(...) instead of delete-reinsert.
    • Strength of fix: Correct combination — constraint enforces invariant at the DB level, update_or_create preserves history at the application level.

    F-21 — Voting endpoint TOCTOU + non-atomic M2M¶

    • Status: RESOLVED
    • Evidence: api/views/views_upgraderequest.py:264-267 — transaction.atomic() + select_for_update() lock the row before reading status + M2M mutations.

    F-22 — Auto-upgrade / auto-downgrade race¶

    • Status: RESOLVED
    • Evidence: api/services/auto_upgrade_service.py:31-32, 72-73, 80 — Member row locked (select_for_update()) before level read + write; LogbookEntry count also locked (select_for_update().count()) to prevent concurrent delete-triggered downgrades double-counting.

    F-25 — ClubNewsNotificationAPIView dict enqueue¶

    • Status: RESOLVED
    • Evidence: api/views/views_pushnotification.py — view now creates the ClubNews row first inside transaction.atomic(), then transaction.on_commit(lambda news=news: send_club_news(news)). The task receives a persisted model instance, not a raw dict.

    F-27 — PII in dry-run logs¶

    • Status: RESOLVED
    • Evidence: api/services/email_notifications.py — logger.info(...) calls now log ID references only (trip.id, member.id, upgrade_request.id, cancellation.member.id), never full email bodies, email addresses, or phone numbers.

    F-32 — HERE Maps cache TTL unit¶

    • Status: RESOLVED
    • Evidence: api/services/here_maps_service.py — all three sites are now consistent with the model's minutes unit. Both memory-cache writes use *60, and DB expiry uses timedelta(minutes=...). tests/test_here_maps_service_unit.py locks this conversion.

    F-35 — SECURE_PROXY_SSL_HEADER scope¶

    • Status: RESOLVED
    • Evidence: ad4x4/settings.py:443 — header now set inside if not DEV: branch. Matches the other SSL settings.

    F-64 — Vehicle.brand max_length=8 clip risk¶

    • Status: RESOLVED
    • Evidence: Migration 0100_alter_member_gender_and_more.py — Vehicle.brand widened to max_length=16.

    F-72 — Member.gender max_length=3 for single-char codes¶

    • Status: RESOLVED
    • Evidence: Migration 0100 — Member.gender tightened to max_length=1 with proper choices=[('M', 'Male'), ('F', 'Female'), ('O', 'Other')].

    F-73 — UpgradeRequest.applicant_reason max_length on TextField¶

    • Status: RESOLVED
    • Evidence: Migration 0100 — misleading max_length=1500 removed from the TextField.

    F-88 — Novita AI CORS leak to production¶

    • Status: RESOLVED
    • Evidence: ad4x4/settings.py:430-431 — Novita AI sandbox regex now inserted into CORS_ALLOWED_ORIGIN_REGEXES only when DEV is true.

    Bonus resolved: F-34 — Model instances passed to Huey tasks¶

    • Status: Partially addressed
    • Evidence: Several enqueue sites switched to passing primary keys (e.g., lambda trip_id=instance.id: create_gallery_for_trip_task(trip_id)). Still some lambdas pass model instances, but the ClubNews + gallery paths are now ID-based.

    Bonus resolved: F-33 — Gallery tasks swallow exceptions¶

    • Status: Likely resolved
    • Evidence: api/services/gallery_webhook.py added idempotency guard (if trip.gallery_id: return gallery_id), min-1 timeout floor, token source normalized. Full exception re-raise behaviour needs secondary verification.

    Still partial or not addressed (confirmed)¶

    F-50 — Avatar 2.5MB limit not enforced via DRF¶

    • Status: RESOLVED
    • Evidence: api/serializers/serializers_member.py:21-23 adds validate_avatar(self, value) and rejects uploads above the 2.5MB limit before the model save path runs.

    F-55 — ClubNewsNotificationAPIView permission check¶

    • Status: RESOLVED
    • Evidence: api/views/views_pushnotification.py:15-29 now uses CanSendClubNewsPermission, which maps to ActionChoice.SEND_CLUB_NEWS in api/permissions.py. Club-news sending now stays on the permission-matrix path instead of a Django-staff check.

    F-89 — Firebase Admin SDK init at settings module load¶

    • Status: RESOLVED
    • Evidence: ad4x4/settings.py no longer initializes Firebase at import time. api/apps.py now exposes initialize_firebase_admin() and calls it from ApiConfig.ready(), keeping startup side effects out of settings import.

    F-24 — Per-channel notification idempotency on retry¶

    • Status: RESOLVED
    • Evidence: api/services/notification_delivery.py now derives a stable channel-specific delivery key, and api/services/notification_service.py wraps every channel send with deliver_notification_once_for_channel(...). Retried tasks skip channels that already completed successfully while still retrying the failing channel.

    F-06 — ClubNews SENT/ERROR delivery state¶

    • Status: RESOLVED
    • Evidence: The SENT/ERROR flip remains correct, and per-channel delivery is now idempotent on retry. A retry no longer re-sends channels that already completed successfully.
