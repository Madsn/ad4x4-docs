    Step 12 — Documentation Drift¶

    Aggregation of doc-vs-reality drift from Steps 1, 2, 3, 4, 5, 6, 8, 9. Each finding cites the CLAUDE.md section and the source-of-truth file:line.

    Drift findings¶

    [medium / confidence high] §5 missing 11+ models¶

    • Source of truth: api/models/*.py
    • Drift: NotificationSettings, TripRegistrationCancellationReason, TripComment, UpgradeRequestComment, LogbookMigrationSkillEntry, Feedback, TripReport, TripReportImage, MeetingPoint, UIString, FaqEntry, Sponsorship — all exist and are referenced via endpoints in §6, but none have a §5 stanza.
    • Severity driver: TripRegistrationCancellationReason is especially bad — it's the audit log for cancellations, referenced by multiple async-task signatures, and completely undocumented.
    • Fix: Add stanzas to §5 for each. Template in raw/03-model-schema.md.

    [medium / confidence high] §7 claims token_version is legacy but the column still exists¶

    • Doc: CLAUDE.md §7 "Member.token_version: legacy, unused… scheduled for removal"
    • Source of truth: api/models/models_member.py (the field is still there per list_models)
    • Drift: Doc promises the cleanup PR but it hasn't landed. Either land the PR or update §7 to soften the wording ("intended for removal in a later PR — still present as of YYYY-MM-DD").
    • Fix: Preferably do the cleanup PR; otherwise add a date marker.

    [medium / confidence high] §6 undocumented rest_registration endpoints¶

    • Doc: CLAUDE.md §6 lists register/, verify-registration/, reset-password/, etc.
    • Source of truth: URL list from list_urls
    • Drift: api/auth/register-email/ and api/auth/verify-email/ are routed to rest_registration views but not in §6.
    • Fix: Either document or remove from URL config. See raw/02-endpoint-drift.md.

    [medium / confidence high] §6 doesn't mention TripCreateView/TripEditView split¶

    • Doc: "Trips (/api/trips/) — Standard CRUD"
    • Source of truth: ad4x4/urls.py + api/views/views_trip.py
    • Drift: POST /api/trips and PUT /api/trips/<pk> (no trailing slash) route to dedicated TripCreateView / TripEditView, not TripViewSet. CRUD is not uniform.
    • Fix: Note the split in §6 with a short rationale.

    [high / confidence high] §3 + §13 claim "~59 test files in api/tests/" — wrong location¶

    • Source of truth: ls api/tests/ shows 3 files; ls tests/ at repo root shows 63 files (per Step 9 architecture agent).
    • Drift: Both §3 (repo layout) and §13 (testing conventions) point at the wrong directory.
    • Fix: Update §3 and §13 to say "~63 test files in tests/ (repo root); api/tests/ holds 3 app-local test files for TBD reason".

    [medium / confidence high] §10 Huey task drift — documented tasks exist, but key mechanics missing¶

    • Source of truth: api/background.py + step 8 agent findings
    • Drift:
    • §10 lists 14 async + 8 periodic tasks — step 8 agent confirmed all are present in code. No task-level drift.
    • But §15 should gain a new gotcha: "Tasks that enqueue from inside a view/signal must use transaction.on_commit(). The repo has zero on_commit usage currently." The step 8 agent confirmed this is a universal gap.
    • Fix: Add on_commit gotcha to §15 after the fix lands. Also cross-reference in §10.

    [medium / confidence high] §19 Graphify counts are stale¶

    • Doc: "2,376 nodes, 7,488 edges, 100 communities"
    • Source of truth: Actual graph reports 2,397 nodes, 7,596 edges, 115 communities (per step 9 agent).
    • Drift: Graphify has been regenerated but the doc wasn't updated.
    • Fix: Update §19 numbers. Also: the "god-node" edge counts in §19 (Level 564, ActionChoice 389, etc.) are 10× inflated because Graphify counts each enum member as a node. The real ranking holds but magnitudes need a footnote.

    [medium / confidence high] §3 says "98 migrations"¶

    • Source of truth: 98 in api/, 3 in website/ = 101 total.
    • Drift: §3 count applies only to the api app; website migrations aren't mentioned.
    • Fix: Either clarify "98 in api/" or update to total.

    [low / confidence high] §2 Python claim 3.13.0 but runtime is 3.13.13¶

    • Patch-level, trivial.
    • Fix: Update §2 Python row.

    [low / confidence high] §11 env var list lists DJANGO_SECRET_KEY etc. but infra/.env.example is the source of truth¶

    • Self-update protocol (§17) says .env.example is authoritative. Verify it still matches §11; any CLAUDE.md additions must flow from .env.example.
    • Fix: Diff infra/.env.example against §11 env var list (not done in this audit — follow-up).

    [low / confidence medium] §2 notes django-oidc-provider 0.9.0 Django 6 compatibility "should be verified" but no verification recorded¶

    • Fix: Run the OIDC provider's integration tests (or smoke-test the /openid/ endpoints) and record the result in §2.

    [low / confidence high] §4 Response-format block says pagination max is 500 but StandardResultsSetPagination default is page_size 10¶

    • Check api/util.py to confirm the 500 max-page-size claim.
    • Fix: Cross-reference and update §6 if the cap has changed.

    [low / confidence high] §15 Doesn't mention LogbookSkillReference lacking a unique constraint¶

    • This surfaced only via Step 6's logbook review agent. New gotcha.
    • Fix: Add entry after the fix lands.

    [low / confidence high] §16 Gallery API, HERE Maps timeout + cache behaviour differs from docs¶

    • Per Step 6 misc-services agent, HERE Maps cache TTL has unit bug (minutes vs seconds vs days). §16 doesn't specify.
    • Fix: Add explicit TTL unit note + timeout note after fix lands.

    [info / confidence high] .claude/skills/SKILL.md mirror — not audited¶

    • Per §17, SKILL.md mirrors CLAUDE.md on specific sections. The audit didn't diff them. Follow-up: diff -r both files for the mirrored sections.

    Summary¶

    Doc drift is present but not severe. The single biggest issue is the test-location claim (§3/§13) — anyone following the doc would look in the wrong place. Second biggest is the 11+ undocumented models in §5.

    Nothing in the doc drift is exploitable; it's all maintainability risk. The Self-Update Protocol (§17) exists but wasn't fully applied on recent changes.

    Recommended doc-update PR (separate from code fixes)¶

    1. Extend §5 with the missing model stanzas.
    2. Correct §3/§13 test location claim.
    3. Update §19 Graphify counts + add inflation caveat on god-node counts.
    4. Document the register-email / verify-email endpoints (or remove them) in §6.
    5. Note the TripCreateView / TripEditView split in §6.
    6. Update §2 Python patch level.
    7. Bump migration count from 98 to "98 in api/ + 3 in website/".
