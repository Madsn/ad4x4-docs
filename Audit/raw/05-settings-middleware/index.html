    Findings¶

    [high / confidence high] SECURE_PROXY_SSL_HEADER is always on, not just in production¶

    • File: ad4x4/settings.py:443
    • Evidence: SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https') is at module scope, not inside if not DEV:.
    • Why this matters: In a local dev setup that's not behind a TLS-terminating proxy, this can cause request.is_secure() to return True if the dev server sees an X-Forwarded-Proto: https header from any client (e.g. curl -H). Not exploitable in normal dev, but it's a subtle bug-waiting-to-happen if a team member runs behind a non-TLS ngrok or similar.
    • Recommendation: Move under if not DEV: to match the other SSL settings.

    [medium / confidence high] rest_framework.authtoken in INSTALLED_APPS appears unused¶

    • Evidence: §7 says the project uses simplejwt, not Token auth. But rest_framework.authtoken is still installed.
    • Recommendation: Remove from INSTALLED_APPS if truly unused. Check migrations for authtoken_token table usage first; if rows exist, plan a drop migration.

    [medium / confidence high] Novita AI sandbox in CORS_ALLOWED_ORIGIN_REGEXES — production exposure¶

    • File: ad4x4/settings.py:428
    • Evidence: ^https://\d+-.*\.sandbox\.novita\.ai$ — presumably a dev-tooling sandbox (AI coding env).
    • Why this matters: This regex allows any *.sandbox.novita.ai subdomain to make CORS requests to prod. If that sandbox gets compromised or abandoned, a malicious actor controlling a matching subdomain could CSRF-read users' data (subject to cookies/credentials, but still).
    • Recommendation: Either (a) restrict to if DEV: (preferred), or (b) pin to a specific sandbox URL used by the team, not a wildcard.

    [medium / confidence high] Firebase Admin SDK initialized at settings.py module load time¶

    • File: ad4x4/settings.py:24–36
    • Evidence: firebase_admin.initialize_app(...) runs every time settings imports, including manage.py check, makemigrations, and tests.
    • Why this matters: (a) slows every command that doesn't need Firebase; (b) fails loudly when credentials aren't set (the print warning is visible even in tests that don't touch FCM); (c) violates Django 6 best practice of deferring init to AppConfig.ready().
    • Recommendation: Move the init into a lightweight AppConfig.ready() in api/apps.py. Falls back gracefully if FCM isn't needed for the current command.

    [low / confidence high] from django.conf.global_settings import SECRET_KEY is dead¶

    • File: ad4x4/settings.py:19
    • Immediately shadowed by lines 70 or 74. Remove.

    [low / confidence high] Hardcoded Hetzner IP in ALLOWED_HOSTS¶

    • File: ad4x4/settings.py:81
    • 78.47.162.184 — works today but brittle to IP change. localhost:50891 at the end is a no-op (Django strips port from ALLOWED_HOSTS).
    • Recommendation: Move IP to env var; drop localhost:50891.

    [low / confidence high] FCM_DJANGO_SETTINGS.ONE_DEVICE_PER_USER = False¶

    • File: ad4x4/settings.py:48
    • Means a user can have multiple registered devices. That's correct product behaviour (phone + tablet), but worth documenting under CLAUDE.md §16.

    [low / confidence medium] DELETE_INACTIVE_DEVICES: True needs verification in practice¶

    • CLAUDE.md §10 says inactive FCM devices are purged after 30 days via periodic_purge_inactive_devices. The fcm_django setting complements that. Confirm both are doing the same thing, not double-deleting.

    [nit / confidence high] '0.0.0.0' in ALLOWED_HOSTS¶

    • File: settings.py:81
    • Not strictly wrong (Django accepts it for local bind), but unusual. Most deployments keep only the public hostname + localhost + 127.0.0.1.
    • Recommendation: Probably safe to drop.

    Positives (verified)¶

    • USE_TZ = False + TIME_ZONE = 'Asia/Dubai' + HUEY.utc = False — triplet is consistent.
    • JWT config matches §7 exactly.
    • Middleware order matches §4 exactly.
    • CORS / CSRF matches §11.
    • Production SSL block is complete.
    • Redis-vs-LocMem cache branch is clean.
    • Throttle rates match §6.

    Follow-ups¶

    1. Move SECURE_PROXY_SSL_HEADER under if not DEV:.
    2. Gate Novita AI sandbox CORS entry with if DEV: — medium priority.
    3. Remove rest_framework.authtoken from INSTALLED_APPS if unused.
    4. Defer Firebase Admin SDK init to AppConfig.ready().
    5. Drop dead SECRET_KEY import and port-qualified ALLOWED_HOSTS entry.
