    Architecture Sweep¶

    Audit of AD4x4 Django backend based on graphify-out/GRAPH_REPORT.md and source verification. Read-only — no source file modified.

    Graph at a glance¶

    • Nodes: 2,397 (CLAUDE.md §19 says 2,376 — drift, minor)
    • Edges: 7,596 (CLAUDE.md §19 says 7,488 — drift, minor)
    • Extraction: 33% EXTRACTED / 67% INFERRED (avg confidence 0.5) — per Graphify's own header. Inferred edges must be treated as hypotheses.
    • Communities: 115 (CLAUDE.md §19 says 100 — drift); 26 of them are empty/single-node noise.

    Top fan-in (god nodes) — verified¶

    Graphify "edges" counts conflate every occurrence (filter class, permission class, serializer, test, admin, migration). Real model-level fan-in is an order of magnitude lower. Verified by grep.

    Rank Node Graphify fan-in Source reality Verdict
    1 Level 566 9 ForeignKey(Level) + 3 M2M(Level) across 5 model files; 46 files touch the name Real load-bearing node. Used as FK from Member, Trip, LogbookSkill, LogbookMigrationRequest, UpgradeRequest, ConfigurableSettings (3 FKs). M2M from PermissionMatrix, ClubNews, NotificationSettings. 566 is heavily inflated but the "god node" label is correct.
    2 ActionChoice 388 TextChoices enum in api/choices.py; 182 occurrences across 21 files, mostly in permissions.py (30) and views Real. Used by every PermissionMatrix check. Anchors the whole authorisation system.
    3 PermissionMatrix 364 Model in api/models/models.py:35; 96 occurrences across 19 files Real. PermissionMatrix.has_permission() is the authoritative perm check, called from 30+ permissions.py classes. Actual call sites: 4 direct invocations (confirmed via grep), but the class is referenced in every permissions.py class body via helpers in permission_service.py.
    4 ApprovalStatus 357 TextChoices enum in api/choices.py:80; 39 occurrences across 8 files Over-inflated. Only views_trip.py (15), signals.py (11), permissions.py (3), views_member.py (3) materially use it. 357 is >10x reality. Still legitimately central to trip lifecycle.
    5 CarBrand 217 TextChoices in api/choices.py:4; narrowly used by Vehicle + Member Over-inflated. Real impact is small — one serializer + one choice endpoint. Appears in the top 10 only because it's a 74-member enum (each member counts).
    6 CountryChoice 197 TextChoices (ISO 3166) in api/choices.py:145 Same pattern as CarBrand. Many enum members, very narrow real usage.
    7 URL configuration for ad4x4 project… 90 = ad4x4/urls.py docstring node — treated as a node with every registered URL as an edge Artifact of Graphify's node model, not a god node.
    8 StandardResultsSetPagination 89 Defined in api/util.py; applied as DRF default pagination Real but shallow. Referenced as a pagination class in almost every ViewSet. Not a "change-at-your-peril" node.
    9 UnifiedResponseSerializer 89 Response envelope {success, message} — used by every view returning non-default shape Real. Changing its shape breaks every client.
    10 Gender 84 3-member enum, narrow use on Member Inflated. Same "big enum → big fan-in" artefact.

    True blast radius of the real god nodes: - Level: changing Level.numeric_level or auto_group affects upgrade, trip-level filtering, permission-matrix scoping, notification targeting. Must-test: member login (defaultuserlevel), trip create (views_trip.py), upgrade voting, auto-upgrade service, permission-matrix filtering. - PermissionMatrix: the has_permission classmethod signature is frozen — it's called from permissions.py and the helpers in api/services/permission_service.py (check_trip_permission_against_perm_matrix_or_trip_lead, etc. — community 14). Changing its kwargs breaks 30+ permission classes. - ActionChoice: adding a value is safe; renaming is not — existing PermissionMatrix rows in the DB reference the old string. - ApprovalStatus: the P/A/R/C state machine is encoded in views_trip.py (1113 LOC) + signals.py trip_post_save / trip_pre_save. Changing a value re-breaks trip count signals.

    Top fan-out (integrators)¶

    Graphify does not publish a fan-out list, but source grep identifies the integrators:

    File Evidence Role
    api/views/views_trip.py (1,113 LOC) Imports 12 api.* modules; 23 top-level classes; imports from background, 3 services, permissions, serializers, models, choices, filters, util The integrator. Trip CRUD, register/unregister, waitlist, approve/decline, check-in/out, search, history, export, view-logbook — all live here.
    api/views/views_member.py (787 LOC) 12 api.* imports Member CRUD + logbook/upgrade/trip-history side endpoints.
    api/services/notification_service.py + friends 5 channel implementations + manager Fans out to email / push / Telegram / store / noop.
    api/background.py Imports init_notifications + gallery_webhook + models Huey task entrypoints — every background action is dispatched through here.
    api/admin.py (281 LOC, 29 ModelAdmin classes) Imports 15+ model names Single flat admin file — reasonable for project size.
    api/permissions.py (525 LOC, 35+ permission classes) Imports ActionChoice, PermissionMatrix, ApprovalStatus, Level Central authorisation surface.
    api/signals.py Imports from background, services.global_settings, services.auto_upgrade_service, 5+ models Glue between ORM events and async tasks.
    ad4x4/urls.py Imports from 27 view modules URL integrator.

    The 5 most tightly-coupled clusters¶

    Graphify's communities are unnamed. Inferred from member nodes:

    • Community 0 (393 nodes, cohesion 0.02) — "Admin & everything-that-references-Level." Hosts every *Admin class plus many models. Low cohesion = Graphify's dumping ground; the Level god node drags half the codebase into this cluster.
    • Community 1 (172 nodes, cohesion 0.05) — "Trip lifecycle." TripsFilter, GalleryWebhookService, CanCreateTripPermission, HasDeleteTripPermission, HasEditTripMediaPermission, HasEditTripPermission, PageNumberPagination. Maps to trip views + permissions + gallery integration.
    • Community 2 (105 nodes, cohesion 0.04) — "Upgrade request + trip request + filters." AreaChoice, TimeOfDayChoice, UpgradeRequestStatus, VoteChoice, LevelsFilter, MeetingPointsFilter, upgrade-request comment filter. Corresponds to member-wish / upgrade-voting domain.
    • Community 3 (81 nodes, cohesion 0.04) — "Payments + profile settings." PayPalConfigurationAdmin, WebsitePaymentAdmin, Emirates, Gender, NotificationSettings, PaymentMethod, PaymentStatus, PayPalConfiguration. Combines website-app payments with member profile side-data.
    • Community 4 (46 nodes, cohesion 0.02) — "Notifications." LoggingContexts, NotificationType, EmailNotificationChannel, every send_*() function (acceptedfromwaitlist, accountdeletioncancelled, accountdeletionrequest, clubwidenews). Corresponds exactly to api/services/notification_service.py + email_notifications.py + friends.
    • Community 5 (67 nodes, cohesion 0.11) — "Member-centric endpoints." ContactInfoMemberSerializer, MembersFilter, AccountDeletionRequest, HasEditMembershipPaymentsPermission, HasSearchMembersPermission, HasViewUpgradeRequestPermissionOrIsForSelf, ListLogbookEntrySerializer. Hosts the member CRUD + personal-logbook seam.

    All five have cohesion under 0.12 — these are not tight clusters, they're loose affinity groups.

    Findings¶

    [medium] Services layer imports from the Huey task module¶

    • Node / area: api/services/trip_registration_service.py → api/background.py
    • Confidence: high (source-verified)
    • Category: layering
    • Evidence: trip_registration_service.py lines 3–7 import send_registration_from_waitlist_notification, send_removed_from_trip_registered_notification, send_removed_from_trip_waitlist_notification from api.background. api.background in turn imports from api.services.init_notifications and api.services.gallery_webhook. No actual import-time cycle (services/init.py does not re-export tripregistrationservice), but this is an upward dependency: services should dispatch via an abstraction, not import task entrypoints directly.
    • Recommendation: Move waitlist-related notification dispatch into notification_service.py (consistent with how notification_manager.send_* is the dispatch seam) and have background.py remain the only file that knows about Huey + service glue. Removes the risk of reintroducing a real cycle.

    [medium] Graphify's fan-in counts over-inflate by ~10x¶

    • Node / area: all top-10 god nodes
    • Confidence: high (source-verified)
    • Category: drift — CLAUDE.md §19 reports these numbers as-is
    • Evidence: Level 566 vs 12 real model-level references; ApprovalStatus 357 vs 39 real occurrences.
    • Recommendation: Treat Graphify's edge counts as relative-ranking only, not absolute blast-radius. The ranking is directionally right; the magnitude is not. Consider adding a one-line caveat to CLAUDE.md §19's "Key structural facts" subsection so future agents don't quote the raw number.

    [medium] views_trip.py is a 1,113-line god file¶

    • Node / area: api/views/views_trip.py
    • Confidence: high (source-verified — 23 top-level classes, 12 service imports)
    • Category: god-file
    • Evidence: Hosts TripCreateView, TripEditView, TripViewSet, RegisterForTrip, ForceRegisterForTrip, RegisterForTripWaitlist, RemoveMemberFromTripRegistration, CancelTripRegistration, AcceptMemberFromWaitlist, TripApproveView, TripDeclineView, TripCheckinView, TripCheckoutView, DetailedMemberTripCountView, TripExportRegistrantsView, TripViewLogbookView, TripSearch, LeadTripHistorySearch — plus two inline serializers.
    • Recommendation: Split into views_trip_core.py (CRUD/Viewset), views_trip_registration.py (register / waitlist / force-register), views_trip_lifecycle.py (approve / decline / checkin / checkout), views_trip_reports.py (export, logbook view, search/history). Matches CLAUDE.md §14 "one file per resource" convention.

    [low] Test directory drift vs CLAUDE.md¶

    • Node / area: tests/ vs api/tests/
    • Confidence: high (source-verified)
    • Category: drift
    • Evidence: CLAUDE.md §3 says api/tests/ contains "~59 test files." Reality: api/tests/ has 3 test files; tests/ at the repo root has 63. Both are discovered by pytest.ini files.
    • Recommendation: Either consolidate into one location or update CLAUDE.md §3 + §13 to describe the split (root tests/ = feature tests, api/tests/ = legacy remnants).

    [low] Graphify count / community drift vs CLAUDE.md §19¶

    • Node / area: CLAUDE.md §19 "Key structural facts"
    • Confidence: high
    • Category: drift
    • Evidence: CLAUDE.md §19 quotes "2,376 nodes, 7,488 edges, 100 communities." Actual graph: 2,397 / 7,596 / 115. God-node edge counts also drift slightly (Level 564 → 566, ActionChoice 389 → 388, PermissionMatrix 364 (matches), ApprovalStatus 357 (matches)).
    • Recommendation: Per §19's own rebuild note, these numbers go stale on every rebuild — consider rephrasing to "approximate" or dropping exact numbers.

    [low] 72 isolated nodes flagged as knowledge gaps¶

    • Node / area: Graphify "Knowledge Gaps" section
    • Confidence: medium (Graphify-only)
    • Category: graph-quality
    • Evidence: 72 nodes with ≤1 connection; views_media.py/serve_media(), upgrade_eligibility.py/get_upgrade_eligibility_data() called out. Both are legitimate, production-used code.
    • Recommendation: No source-side action needed. This is a signal that Graphify's extractor missed imports for some utility files, not a codebase defect.

    [info] No structural cycles, no services→views, no models→services¶

    • Confidence: high (source-verified)
    • Evidence: grep for from api.views in api/services/ and api/models/ returns zero matches; grep for from api.services in api/models/ returns zero matches. Layering invariants hold: models ← services ← views, and services import background for task dispatch (one-way).

    Graphify false positives¶

    All top-10 god-node edge counts are inflated — these are the worst offenders when interpreted as "change blast radius":

    1. Level claimed 566 edges. True model-level fan-in is 12 (9 FK + 3 M2M). Every file that mentions the word "Level" is scored as an edge.
    2. ApprovalStatus claimed 357 edges. Real usage is concentrated in 8 files, 39 occurrences. Most "edges" are to test functions, serializer fields, and admin displays that merely reference the enum class.
    3. CarBrand claimed 217 edges. Real structural usage is one CharField(choices=CarBrand.choices) on Vehicle + a choices endpoint. The 217 comes from the 74 enum members each generating "edges."
    4. Gender claimed 84 edges — same pattern. 3-member enum, narrow use, artificially boosted by Graphify treating enum members as nodes.
    5. "URL configuration for ad4x4 project…" (the urls.py docstring) claimed 90 edges. This is a node type (docstring-as-node), not a real god class.

    Summary¶

    • Three true god nodes (Level, PermissionMatrix, ActionChoice) and one god file (views_trip.py, 1,113 LOC) are the real blast-radius concerns. The other top-10 entries are Graphify artefacts.
    • Layering is clean: no models→services, no services→views, no import cycles at load time. One soft upward dependency: services/trip_registration_service.py → background.py — worth refactoring but not urgent.
    • CLAUDE.md §3, §13, §19 have drifted from reality (test-dir split and graph counts). Quick doc fix; no code change needed.
