    AD4x4 Website Implementation Plan¶

    Overview¶

    Build a companion website to the AD4x4 mobile app focused on payment processing to avoid Apple/Google app store commissions. The website shares the same Member database and authentication as the existing backend.

    Target Users: Potential and existing members who want to pay for premium membership via the web to avoid in-app purchase fees.

    1. Current Architecture Analysis¶

    Existing Backend¶

    • Member Model: api/models/models_member.py - extends AbstractUser
    • Payment Field: paid_member (BooleanField, default=False) - exists
    • Payment Endpoint: POST /api/members/<id>/payments - requires edit_membership_payments permission
    • Authentication: JWT via SimpleJWT + rest_registration library
    • Email: Already configured (Gmail SMTP)

    Rest_registration Already Provides¶

    • /api/auth/login/ - Login
    • /api/auth/register/ - Registration
    • /api/auth/password/reset/ - Password reset (URL configured: https://web.ad4x4.com/reset-password)
    • /api/auth/password/reset/confirm/ - Password reset confirmation

    Settings Already in Place¶

    • Django templates: Configured in TEMPLATES
    • Static files: Configured (STATIC_ROOT, STATICFILES_DIRS)
    • ALLOWED_HOSTS: Includes web.ad4x4.com (via existing config)

    2. Requirements Summary¶

    Feature Description
    Signup Member registration via web form
    Login Existing member login
    Password Recovery Reset password flow
    App Store Links Links to download the mobile apps
    PayPal Payment One-time payment to set paid_member=True
    Payment Verification Server-side via PayPal IPN/webhook

    3. Implementation Plan¶

    Phase 1: Project Setup & Configuration¶

    1.1 Create Website App¶

    • Create new Django app: python manage.py startapp website
    • Add 'website' to INSTALLED_APPS in settings.py
    • Create website/ directory structure with views.py, urls.py, templates/

    1.2 URL Configuration¶

    • Add website URLs to ad4x4/urls.py:
    • / - Home/Landing page
    • /signup/ - Registration page
    • /login/ - Login page
    • /logout/ - Logout page
    • /reset-password/ - Password reset (can use rest_registration template)
    • /reset-password/confirm/<reset_token>/ - Password reset confirm
    • /payment/ - Payment page
    • /payment/success/ - Payment success page
    • /payment/cancel/ - Payment cancel page
    • /payment/webhook/ - PayPal webhook endpoint

    1.3 Static Files & Media¶

    • Create static/website/ directory for CSS, JS, images
    • Create basic styling (or use existing CSS framework)
    • Add app store badge images (Apple App Store, Google Play)

    Phase 2: Authentication Views (Django Templates)¶

    2.1 Base Template¶

    • Create templates/website/base.html
    • Include navbar with logo, login/logout links
    • Include footer with app store links
    • Add Bootstrap 5 CDN (or Tailwind)

    2.2 Login View¶

    • Create templates/website/login.html
    • Form: username/email, password, remember me
    • Link to password reset
    • Link to signup
    • Implement website/views.py:LoginView using Django's authenticate() + session login
    • Handle "next" parameter for redirect after login

    2.3 Signup View¶

    • Create templates/website/signup.html
    • Form: username, email, password, confirm password
    • Use existing MemberRegistrationSerializer logic
    • Implement website/views.py:SignupView
    • On success: auto-login and redirect to payment page

    2.4 Password Reset Views¶

    • Use rest_registration's built-in templates OR create custom
    • Create templates/website/password_reset.html - request reset
    • Create templates/website/password_reset_confirm.html - set new password
    • Configure rest_registration to use custom template paths

    2.5 Logout View¶

    • Implement website/views.py:LogoutView
    • Use Django's logout() function
    • Redirect to home page

    Phase 3: PayPal Integration¶

    3.1 PayPal Configuration¶

    • Add to settings.py: python PAYPAL_CLIENT_ID = os.getenv('PAYPAL_CLIENT_ID') PAYPAL_CLIENT_SECRET = os.getenv('PAYPAL_CLIENT_SECRET') PAYPAL_MODE = 'live' # or 'sandbox' PAYPAL_PRODUCT_PRICE = '9.99' # one-time payment amount
    • Get PayPal client ID/secret from PayPal Developer Dashboard

    3.2 PayPal JS SDK Integration¶

    • Add PayPal SDK script to payment template
    • Create JavaScript to render PayPal buttons
    • Handle order creation and capture

    3.3 Payment View¶

    • Create templates/website/payment.html
    • Display pricing, features of paid membership
    • Show PayPal button
    • On successful payment:
    • Capture order via PayPal API
    • Set member.paid_member = True
    • Redirect to success page

    3.4 Webhook Handler (Server-side Verification)¶

    • Create website/views.py:PayPalWebhookView
    • Endpoint: POST /payment/webhook/
    • Verify webhook signature
    • Handle PAYMENT.CAPTURE.COMPLETED event
    • Fallback: Also support client-side order capture for immediate feedback

    3.5 Success/Cancel Pages¶

    • Create templates/website/payment_success.html
    • Create templates/website/payment_cancel.html
    • Display appropriate messages

    Phase 4: Payment Logic Integration¶

    4.1 API Endpoint for Setting Paid Status¶

    • Create new endpoint (or modify existing): POST /api/website/mark-paid/
    • Accept: memberid, paypalorderid, paypaltransaction_id
    • Verify transaction with PayPal API
    • Set member.paid_member = True
    • Log payment for audit trail
    • Protect with CSRF + authentication

    4.2 Payment Model (Optional - for records)¶

    • Create WebsitePayment model:
    • member (FK to Member)
    • amount
    • currency
    • paypalorderid
    • paypaltransactionid
    • status (pending, completed, failed)
    • createdat, updatedat

    Phase 5: Home & Landing Pages¶

    5.1 Home Page¶

    • Create templates/website/home.html
    • Hero section with app description
    • App store download buttons (prominent)
    • "Upgrade to Premium" CTA (for logged-in non-paying members)
    • Features overview

    5.2 Authenticated Home (for logged-in users)¶

    • Show personalized content based on membership status
    • If not paid_member: show upgrade prompt
    • If paid_member: show "You're a premium member"

    Phase 6: Security & Production¶

    6.1 CSRF & Authentication¶

    • Ensure all forms use {% csrf_token %}
    • Use @login_required decorator on views requiring auth
    • Configure session authentication (add to DEFAULT_AUTHENTICATION_CLASSES)

    6.2 Environment Variables¶

    • Document required env vars:
    • PAYPAL_CLIENT_ID
    • PAYPAL_CLIENT_SECRET
    • PAYPAL_MODE (sandbox/live)

    6.3 Docker & Infrastructure¶

    The website uses the same domain as the API (ap.ad4x4.com) - website at /, API at /api/.

    6.3.1 Docker Configuration¶

    • Add website app files to Dockerapp: dockerfile # Add website app COPY --chown=appuser:appuser ./website ./website COPY --chown=appuser:appuser ./static/website ./static/website

    • Pass PayPal env vars to ad4x4-app container in docker-compose

    6.3.2 Nginx Configuration¶

    No separate vhost needed - website served at /, API at /api/:

    • Existing nginx config already handles this pattern
    • Website URLs don't conflict with API routes

    6. Key Implementation Details¶

    Authentication Decision¶

    The website uses session authentication (different from the app's JWT): - Add rest_framework.authentication.SessionAuthentication to settings - Use Django's auth.login() / auth.logout() - The API endpoints for payment use JWT but website uses session

    Member Sync¶

    • Website and app share same Member model
    • Member registers on website → appears in app
    • Member pays on website → paid_member=True → works in app

    PayPal Flow¶

    1. User clicks PayPal button on payment page
    2. PayPal SDK shows checkout UI
    3. User approves payment
    4. JavaScript captures order, gets transaction ID
    5. JS sends transaction ID to Django endpoint
    6. Django verifies with PayPal API (server-side)
    7. Django sets member.paid_member = True
    8. Redirect to success page

    • App store links open correct stores
