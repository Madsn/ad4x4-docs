    Trips¶

    This document outlines the API endpoint for searching trips. For general trip management, please refer to the Trips document.

    Search Trips¶

    Search for trips by title, with optional filters for level, date ranges, meeting point, and area. This endpoint is useful for finding specific trips, browsing trip history, or discovering trip activities.

    Endpoint: GET /api/trips/search/

    Authentication: Required (Bearer token) Permission Required: Users must have SEARCH_TRIPS permission to access this endpoint.

    Query Parameters¶

    Parameter Type Required Description
    query string Yes Search term - must be at least 3 characters. Matches against trip title (case-insensitive partial match)
    level integer No Trip level ID for filtering to include only trips at a specific level
    min_level integer No Minimum level numeric value for filtering to include only trips at this level or higher (inclusive)
    max_level integer No Maximum level numeric value for filtering to include only trips at this level or lower (inclusive)
    start_date_min date (ISO 8601) No Filter for trips starting from this date (inclusive)
    start_date_max date (ISO 8601) No Filter for trips starting until this date (inclusive)
    end_date_min date (ISO 8601) No Filter for trips ending from this date (inclusive)
    end_date_max date (ISO 8601) No Filter for trips ending until this date (inclusive)
    meeting_point integer No Filter for trips at a specific meeting point (exact match by ID)
    area string No Filter for trips in a specific area
    page integer No Page number (default: 1)
    page_size integer No Number of results per page (default: 20, max: 500)

    Request Examples¶

    Basic search:

    curl -X GET "http://api.example.com/api/trips/search/?query=fun" \
  -H "Authorization: Bearer <your-token>"

    Search with level filter:

    curl -X GET "http://api.example.com/api/trips/search/?query=adventure&level=10" \
  -H "Authorization: Bearer <your-token>"

    Search with date range:

    curl -X GET "http://api.example.com/api/trips/search/?query=expedition&start_date_min=2024-01-01&end_date_max=2024-12-31" \
  -H "Authorization: Bearer <your-token>"

    Search by meeting point:

    curl -X GET "http://api.example.com/api/trips/search/?query=beach&meeting_point=1" \
  -H "Authorization: Bearer <your-token>"

    Search by area:

    curl -X GET "http://api.example.com/api/trips/search/?query=desert&area=DUBAI" \
  -H "Authorization: Bearer <your-token>"

    Paginated search:

    curl -X GET "http://api.example.com/api/trips/search/?query=trip&page=1&page_size=10" \
  -H "Authorization: Bearer <your-token>"

    Error Responses¶

    Error Response (400 Bad Request - Missing query):

    {
  "success": false,
  "message": "query_parameter_required"
}

    Error Response (400 Bad Request - Query too short):

    {
  "success": false,
  "message": "query_too_short"
}

    Error Response (403 Forbidden):

    {
  "detail": "You do not have permission to perform this action."
}

    Notes¶

    • The search is case-insensitive and performs partial matching (contains) on trip titles
    • Query must be at least 3 characters long
    • Results are ordered by start_time (descending), then by id (ascending)
    • Results are paginated using standard pagination (20 items per page by default)
    • Level filtering: Use level for exact level match, or min_level/max_level for range filtering
    • Example: ?level=10 returns only Newbie trips
    • Example: ?min_level=100 returns Intermediate and higher level trips
    • Example: ?max_level=100 returns Newbie and Intermediate level trips
    • Date filtering: Use start_date_min/max and end_date_min/max to filter by date ranges
    • Trips that have ended (cut_off is in the past) are automatically excluded from results
    • If end_date_max is set without end_date_min, only trips ending on or before that date are included
    • Similarly for start dates
    • Meeting point filtering: Use meeting_point to filter by exact meeting point ID
    • Area filtering: Use area to filter by meeting point area code
    • Permission Required: Users must have SEARCH_TRIPS permission. By default, this is granted to Newbie level and above.
    • Performance Note: This endpoint searches trip titles efficiently. Searching by trip lead's user info (username, first name, last name) requires additional database joins and can be slower with many trips. Use title-based search for better performance.
    • User-specific information: For authenticated users, the response includes trip-specific registration status:
    • isRegistered: Whether the authenticated user is registered for this trip
    • isWaitlisted: Whether the authenticated user is on the waitlist for this trip
    • waitlistCount: Current number of users on the waitlist
    • registeredCount: Current number of users registered for this trip

    Use Cases¶

    • Finding specific trips by title search
    • Browsing available trips for a specific level (e.g., Newbie trips only)
    • Discovering trip activities by date range
    • Finding trips at specific meeting points
    • Exploring trips in specific geographic areas
    • Checking trip history for a user or level
    • Building trip calendars or schedules
