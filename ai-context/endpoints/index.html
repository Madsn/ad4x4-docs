    API Endpoints¶

    AI-context reference. schema.yml (root) is the canonical source — auto-generated by python manage.py spectacular --file schema.yml after any endpoint change. This file is a navigable summary grouped by resource; if it disagrees with schema.yml, schema.yml wins.

    All endpoints are under /api/. Authentication header: Authorization: Bearer <jwt_token>. Response envelope and pagination rules: see architecture.md.

    Authentication (/api/auth/)¶

    Method Path Description
    POST /api/auth/login/ Login by login/username/email + password. Returns {access, refresh} wrapped in the unified envelope. Implemented by api.views.views_auth.LoginView, mounted before rest_registration's URLs so it shadows them.
    POST /api/auth/logout/ Body: {"refresh": "<token>"}. Blacklists only that single session. Idempotent.
    POST /api/auth/logout-all/ Blacklists every outstanding refresh token for the user (all devices, current included).
    GET /api/auth/sessions/ Lists the authenticated user's outstanding (non-blacklisted) refresh-token sessions (jti, created_at, expires_at only — never the raw token).
    DELETE /api/auth/sessions/ Body: {"keep_refresh": "<current session refresh token>"} (optional). Blacklists every session except the one whose refresh token is supplied. Without keep_refresh behaves like logout-all.
    POST /api/auth/register/ Register new member (rest_registration)
    POST /api/auth/register-email/ Register / change an email address
    POST /api/auth/verify-email/ Verify an email address
    POST /api/auth/verify-registration/ Verify email (rest_registration)
    POST /api/auth/reset-password/ Reset password (rest_registration)
    POST /api/auth/send-reset-password-link/ Send reset email
    POST /api/auth/change-password/ Change password. Blacklists every outstanding refresh token for the user — see gotchas.
    POST /api/auth/handoff/mint/ App-only. Mints a single-use, short-TTL handoff token for the authenticated member. Returns {token, expiresAt}; only the SHA-256 hash is persisted. Token is appended as ?handoff=<token> to the public pay/manage URL. TTL via HANDOFF_TOKEN_TTL_SECONDS (default 300).
    POST /api/auth/handoff/exchange/ Public. Body: {"token": "<cleartext>"}. Atomically consumes the token and returns {access, refresh} (same shape as /api/auth/login/). Errors: 400 handoff_invalid, 410 handoff_expired, 410 handoff_consumed, 401 handoff_invalid if the member has been deactivated.
    GET/PUT/PATCH /api/auth/profile/ Member profile (rest_registration)
    GET/PUT/PATCH /api/auth/profile/notificationsettings Notification preferences
    POST /api/token/ Alias for /api/auth/login/
    POST /api/token/refresh/ Exchange a refresh token for a new {access, refresh} pair. Refresh tokens rotate — see gotchas.

    Members (/api/members/)¶

    Standard CRUD ViewSet plus: /leadsearch, /search, /activetripleads, /request-deletion, /deletion-request, /cancel-deletion /<pk>/upgradeeligibility, /<pk>/payments, /<pk>/subscription, /<pk>/tripcounts, /<pk>/triphistory /<pk>/triprequests, /<pk>/upgraderequests, /<pk>/logbookentries, /<pk>/logbookskills, /<pk>/logbookskills/export, /<pk>/feedback

    POST /<pk>/payments (admin, EDIT_MEMBERSHIP_PAYMENTS) sets lifetime membership status: {payment_received: true} grants it (records a MANUAL_GRANT event) and {payment_received: false} revokes it (records a REFUND event). An optional {note} is stored on the event to explain the action in the audit trail. Each writes a SubscriptionPaymentEvent. Members list accepts ?subscription_status=active|lapsed|exempt.

    POST /<pk>/payments/<payment_id>/refund (admin, EDIT_MEMBERSHIP_PAYMENTS) reverses a captured PayPal payment via PayPal's refund API. payment_id is a WebsitePayment.id (no endpoint currently exposes this id — see issue #229). Requires the payment to be COMPLETED with a capture id; under a row lock it marks the WebsitePayment REFUNDED, records a REFUND/paypal SubscriptionPaymentEvent (refund id = idempotency key), and revokes paid_member unless another COMPLETED payment remains. {note} required. PayPal errors → 400; duplicate refund id → 409. Not reversible via the API.

    GET /<pk>/subscription (admin, VIEW_MEMBERSHIP or EXPORT_SUBSCRIPTION_PAYMENTS) returns one member's subscription panel: {memberId, status, reason, paidMember, events[]}, where each event exposes the audit columns (source, createdBy, note, receiptUrl) hidden from the member-facing history. Read-only.

    Member serializers expose the computed subscriptionStatus (active=paid / lapsed=unpaid / exempt). The profile/detail serializer (ProfileSerializer) additionally exposes subscriptionReason (paid/comped/exempt/lapsed) and the read-only isSuperuser flag; neither is included on the list serializer.

    Trips (/api/trips/)¶

    List/retrieve are served by TripViewSet; create/update/delete use the dedicated TripCreateView and TripEditView routes without trailing slashes (POST /api/trips, PUT/PATCH/DELETE /api/trips/<pk>). Additional actions:

    /search, /lead-trip-history /<pk>/register, /<pk>/unregister, /<pk>/removemember, /<pk>/waitlist /<pk>/addfromwaitlist, /<pk>/forceregister /<pk>/approve, /<pk>/decline /<pk>/checkin, /<pk>/checkout /<pk>/comments, /<pk>/tripreports /<pk>/exportregistrants (CSV download) /<pk>/viewlogbooks, /<pk>/logbook-entries

    Two-step overlap guard¶

    Trip create/register/waitlist have a two-step overlap guard. If the chosen lead or registering member has an approved or pending overlapping trip where they are registered or primary lead, the first request returns 409 with message: "trip_overlap_warning" and structured warnings; no mutation happens. Clients retry the same request with confirmOverlap: true to proceed. Waitlist-only and deputy-lead roles do not count as conflicts; exact boundary-touching times do not overlap.

    Logbook¶

    /api/logbookentries/, /api/logbookskills/, /api/logbookskillreferences/, /api/logbook-migrations/, /api/logbookentries/export, /api/marshal-activity/export

    Full CRUD on logbook entities.

    Who can sign a logbook entry¶

    Creating/updating/deleting a logbook entry (/api/logbookentries/, and POST /api/trips/<pk>/logbook-entries) requires one of: - Being the trip's lead or a deputy lead (Trip.is_lead_for_user) — always allowed. - Holding create_logbook_entries_superuser for the trip's level — bypasses every other check, including trip attendance. - Holding plain create_logbook_entries (scoped or unscoped) for the trip's level, and the signer themselves being a checked-in TripRegistration on that same trip. This models peer sign-off: an ordinary marshal can only verify skills for a trip they personally attended.

    A 403 from this check returns one of two distinct message values so clients don't conflate the two causes: - missing_create_logbook_entries_permission — the signer holds no matching grant at all. - not_checked_in_for_trip — the signer holds create_logbook_entries but wasn't checked in on this trip themselves. Granting create_logbook_entries_superuser (or making them trip lead/deputy) removes this requirement.

    GET /api/logbookentries/ (list) is separately gated on the CREATE_LOGBOOK_ENTRIES permission action — 403 without it. retrieve/create/update/destroy are unaffected by this and follow the rules above. The list also supports filtering by member, trip, signed_by, and created_at (date range), plus ordering on created_at/id.

    See check_logbook_entry_permissions in api/services/permission_service.py.

    CSV exports¶

    Three streaming CSV endpoints, gated by a dedicated EXPORT_LOGBOOK_DATA permission (separate from CREATE_LOGBOOK_ENTRIES, so export access can be granted/revoked independently of signing rights): - GET /api/logbookentries/export — respects the same filterset/ordering as GET /api/logbookentries/. - GET /api/members/<pk>/logbookskills/export — one member's skill sign-offs. No self-access exception (unlike the JSON read endpoint) — EXPORT_LOGBOOK_DATA is required even for your own data. - GET /api/marshal-activity/export — the per-marshal aggregate rollup (same computation as marshalBreakdown on the aggregate endpoint), one row per marshal.

    Column allow-list across all three: record ids, member/signer username + full name + level, trip id/title/date, skill names, sign-off/aggregate counts, comment, created/last-activity timestamps. Excluded: email, phone, DOB, ICE, address.

    GET/POST /api/logbook-migration-attachments/ — list (own migration requests, or all if APPROVE_LOGBOOK_MIGRATION) or upload a file. Multipart form: migration_request (int PK) + file. Accepted types: application/pdf, image/jpeg, image/png, image/webp — validated by magic bytes, not MIME header. Images are EXIF-stripped before storage. Limits from ConfigurableSettings (per-file, total, count). Create/delete require either owning the migration request while it is DRAFT/PENDING/RETURNED, or holding APPROVE_LOGBOOK_MIGRATION (or superuser). DELETE /api/logbook-migration-attachments/<id>/ — same ownership/status rule as create. Attachments are returned as a nested attachments[] array on LogbookMigrationRequest detail/list responses; the old single uploaded_pdf field has been removed.

    Upgrade Requests (/api/upgraderequests/)¶

    /<pk>/comments, /<pk>/approve, /<pk>/decline, /<pk>/vote, /<pk>/voted /latestapproved, /voted

    GET/POST /api/upgrade-request-attachments/ — list (requires VIEW_UPGRADE_REQ) or upload a file (requires CREATE_UPGRADE_REQ_FOR_SELF or CREATE_UPGRADE_REQ_FOR_OTHERS). Multipart form: upgrade_request (int PK) + file. Accepted types: application/pdf, image/jpeg, image/png, image/webp — validated by magic bytes, not MIME header. Images are EXIF-stripped before storage. Limits from ConfigurableSettings (per-file, total, count). DELETE /api/upgrade-request-attachments/<id>/ — requires DELETE_UPGRADE_REQ for the attachment's request's target_level. Attachments are returned as a nested attachments[] array on upgrade request detail/list responses.

    Membership (one-time lifetime payment)¶

    • GET /api/subscription — current user's verdict {status, reason, gatingMode, price, currency, gatedActions[]}. status ∈ active(paid)/lapsed(unpaid)/exempt; reason ∈ exempt/paid/comped/lapsed; gatingMode ∈ off/soft/hard (lets clients show a soft warning banner without a 403); gatedActions is the backend-owned list of gated action keys (enforced + cosmetic). price/currency reflect what the member is actually charged: they come from PayPalConfiguration.display_amount/display_currency when PayPal is configured and is_active, and fall back to ConfigurableSettings.annual_subscription_price/annual_subscription_currency only when PayPal is absent or inactive (fresh/dev or paused intake) — keeping advertised == charged (issue #217).
    • POST /api/subscription/subscribe — create a one-time PayPal order and return {approvalUrl, orderId}. The PayPal order's return_url/cancel_url point at the routes below; capture + the lifetime grant happen there (grant_membership, sets paid_member=True).
    • GET /api/subscription/stats — club-wide membership aggregate for the admin dashboard (VIEW_MEMBERSHIP; treasurers hold it via EXPORT_SUBSCRIPTION_PAYMENTS). Returns {active, lapsed, exempt, total, revenueThisMonth, revenueYtd, currency, asOf} — counts over active member rows (exempt wins over paid), revenue = gross payment_completed amounts in the period (decimal strings). Read-only, cached privately ~120 s.
    • GET /api/subscription/payments — member's own payment history (paginated).
    • GET /api/subscription/payments/<event_id>/receipt — printable HTML receipt / tax invoice for a single priced payment event. Owner, or treasurer (EXPORT_SUBSCRIPTION_PAYMENTS) for anyone's; only events with an amount have a receipt.
    • GET /api/admin/subscription-payments/ — paginated, filterable JSON ledger of SubscriptionPaymentEvents for the treasurer (EXPORT_SUBSCRIPTION_PAYMENTS). Filters: ?from=&to=&eventType=&source=&memberId= (ISO dates / int validated → 400). Rows carry the export columns. Distinct from the CSV …/export below.
    • GET /api/admin/subscription-payments/export?from=&to=&format=csv — treasurer CSV export (EXPORT_SUBSCRIPTION_PAYMENTS); also a Django admin action.

    Two non-API routes (api.views.views_payment, wired directly in ad4x4/urls.py) complete the subscribe flow (no trailing slash — they must match the PAYPAL_SUBSCRIPTION_RETURN_URL / PAYPAL_SUBSCRIPTION_CANCEL_URL defaults exactly): - GET /subscription/return — PayPal sends the approving browser here. Resolves the member from the pending WebsitePayment by paypal_order_id (no session/login — SPA/mobile clients use JWT, so the redirected browser carries no Django cookie; the order token is the capability), captures the order, grants the pass (the row flip + grant share one transaction.atomic() under select_for_update), then 302-redirects to the Next portal. An already-COMPLETED order short-circuits without re-capturing, and a duplicate/raced capture self-heals to status=success. Capture is on-return, not automatic: PayPal does not capture an intent=CAPTURE order on its own, so a user who approves but never returns leaves the order uncaptured (no grant — correctly "not completed"). The PAYMENT.CAPTURE.COMPLETED webhook is not a backstop for that case; it backstops the other one — a capture that succeeded but whose grant write failed and rolled the row back to PENDING (the webhook then re-grants; both paths dedupe on paypal_order_id). - GET /subscription/cancel — 302-redirects to the portal. - Portal target is SUBSCRIPTION_PORTAL_RETURN_URL (env-overridable; default https://new.ad4x4.com/portal/membership/return until the front-end apex cutover), with an outcome ?status=success|error|cancel appended.

    The one-time-order flow (/payment/create-order/, /payment/approve/, /payment/capture-order/, /payment/webhook/ — api.views.views_payment, no HTML pages; the Django website app that used to serve those pages was removed in issue #347) still exists and shares the same grant_membership + PAYMENT.CAPTURE.COMPLETED webhook. There is no recurring subscription or PayPal Subscriptions webhook (the rolling-subscription model was reverted — issue #169) — the /subscription/cancel route above is only the PayPal approval-cancel return, not a subscription-cancel API.

    Gating: logbook skill sign-off (gates the signee) and upgrade-request creation (gates the applicant) return 403 {detail, code: "subscription_required"} when the gated member is lapsed (unpaid) and gating_mode is hard. soft reports unpaid without blocking; off disables gating entirely. Clients branch on code, not the bare 403.

    Kit items, vouchers & marshal inventory¶

    • /api/kit-items/ (+ /<pk>/) — CRUD ViewSet for KitItem.
    • /api/kit-entitlements/ (+ /<pk>/) — CRUD ViewSet for KitEntitlement (per-item level entitlement rule).
    • GET /api/membership-price/ — public; the currently advertised membership price (displayAmount/displayCurrency + the PayPal charge paymentAmount).
    • Kit voucher flow (single-use token, for handing kit to a member): GET /api/kit-voucher/ (the member's own voucher), POST /api/kit-voucher/token/ (mint a redemption token), POST /api/kit-voucher/lookup/ (marshal resolves a token), POST /api/kit-voucher/redeem/ (collect items).
    • Marshal stock inventory:
    • GET /api/kit-inventory/ — all marshals' summaries (MANAGE_KIT_INVENTORY).
    • GET /api/kit-inventory/me/ — the calling marshal's own summary + event ledger (ACCESS_MARSHAL_PANEL).
    • GET /api/kit-inventory/<marshal_id>/ — one marshal's summary + ledger (MANAGE_KIT_INVENTORY).
    • POST /api/kit-inventory/<marshal_id>/events/ — record a MarshalStockEvent (MANAGE_KIT_INVENTORY); ISSUE events are system-only. Ledger rows expose createdByUsername (issue #214).
