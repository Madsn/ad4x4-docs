    API Endpoints¶

    AI-context reference. schema.yml (root) is the canonical source — auto-generated by python manage.py spectacular --file schema.yml after any endpoint change. This file is a navigable summary grouped by resource; if it disagrees with schema.yml, schema.yml wins.

    All endpoints are under /api/. Authentication header: Authorization: Bearer <jwt_token>. Response envelope and pagination rules: see architecture.md.

    Authentication (/api/auth/)¶

    Method Path Description
    POST /api/auth/login/ Login by login/username/email + password. Returns {access, refresh} wrapped in the unified envelope. Implemented by api.views.views_auth.LoginView, mounted before rest_registration's URLs so it shadows them.
    POST /api/auth/logout/ Body: {"refresh": "<token>"}. Blacklists only that single session. Idempotent.
    POST /api/auth/logout-all/ Blacklists every outstanding refresh token for the user (all devices, current included).
    GET /api/auth/sessions/ Lists the authenticated user's outstanding (non-blacklisted) refresh-token sessions (jti, created_at, expires_at only — never the raw token).
    DELETE /api/auth/sessions/ Body: {"keep_refresh": "<current session refresh token>"} (optional). Blacklists every session except the one whose refresh token is supplied. Without keep_refresh behaves like logout-all.
    POST /api/auth/register/ Register new member (rest_registration)
    POST /api/auth/register-email/ Register / change an email address
    POST /api/auth/verify-email/ Verify an email address
    POST /api/auth/verify-registration/ Verify email (rest_registration)
    POST /api/auth/reset-password/ Reset password (rest_registration)
    POST /api/auth/send-reset-password-link/ Send reset email
    POST /api/auth/change-password/ Change password. Blacklists every outstanding refresh token for the user — see gotchas.
    GET/PUT/PATCH /api/auth/profile/ Member profile (rest_registration)
    GET/PUT/PATCH /api/auth/profile/notificationsettings Notification preferences
    POST /api/token/ Alias for /api/auth/login/
    POST /api/token/refresh/ Exchange a refresh token for a new {access, refresh} pair. Refresh tokens rotate — see gotchas.

    Members (/api/members/)¶

    Standard CRUD ViewSet plus: /leadsearch, /search, /activetripleads, /request-deletion, /deletion-request, /cancel-deletion /<pk>/upgradeeligibility, /<pk>/payments, /<pk>/tripcounts, /<pk>/triphistory /<pk>/triprequests, /<pk>/upgraderequests, /<pk>/logbookentries, /<pk>/logbookskills, /<pk>/feedback

    POST /<pk>/payments (admin, EDIT_MEMBERSHIP_PAYMENTS) adjusts subscription expiry: {grant_months: N} (extend), {expires_at: <dt>} (set explicit comp/correction), or legacy {payment_received: bool}. Each writes a SubscriptionPaymentEvent. Members list accepts ?subscription_status=active|lapsed|exempt.

    List/detail member serializers expose the computed subscription contract: subscriptionStatus (active/lapsed/exempt), subscriptionExpiresAt (null for exempt), subscriptionDaysRemaining.

    Trips (/api/trips/)¶

    List/retrieve are served by TripViewSet; create/update/delete use the dedicated TripCreateView and TripEditView routes without trailing slashes (POST /api/trips, PUT/PATCH/DELETE /api/trips/<pk>). Additional actions:

    /search, /lead-trip-history /<pk>/register, /<pk>/unregister, /<pk>/removemember, /<pk>/waitlist /<pk>/addfromwaitlist, /<pk>/forceregister /<pk>/approve, /<pk>/decline /<pk>/checkin, /<pk>/checkout /<pk>/comments, /<pk>/tripreports /<pk>/exportregistrants (CSV download) /<pk>/viewlogbooks, /<pk>/logbook-entries

    Two-step overlap guard¶

    Trip create/register/waitlist have a two-step overlap guard. If the chosen lead or registering member has an approved or pending overlapping trip where they are registered or primary lead, the first request returns 409 with message: "trip_overlap_warning" and structured warnings; no mutation happens. Clients retry the same request with confirmOverlap: true to proceed. Waitlist-only and deputy-lead roles do not count as conflicts; exact boundary-touching times do not overlap.

    Membership (v1 annual pass)¶

    • GET /api/subscription — current user's verdict {status, reason, expiresAt, daysRemaining, price, currency, gatedActions[]}. status ∈ active/lapsed/exempt; reason ∈ exempt/paid/grandfathered/comped/lapsed; gatedActions is the backend-owned list of gated action keys (enforced + cosmetic).
    • POST /api/subscription/subscribe — create a one-time PayPal order (the annual pass) and return {approvalUrl, orderId}. Capture + the +12-month grant happen in the website order-capture / webhook paths (grant_annual_pass).
    • GET /api/subscription/payments — member's own payment history (paginated).
    • GET /api/admin/subscription-payments/export?from=&to=&format=csv — treasurer CSV export (EXPORT_SUBSCRIPTION_PAYMENTS); also a Django admin action.

    Payment capture/webhook is the existing website one-time-order flow (/payment/...), repurposed to grant the pass. There is no recurring subscription, /cancel, or subscriptions webhook in v1 (deferred to Phase 2).

    Gating: logbook skill sign-off (gates the signee) and upgrade-request creation (gates the applicant) return 403 {detail, code: "subscription_required", expiresAt} when the gated member is lapsed and subscription_gating_enabled is on. Clients branch on code, not the bare 403.
