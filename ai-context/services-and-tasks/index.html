    Services Layer & Background Tasks¶

    AI-context reference. Views must be thin. All business logic lives in api/services/. Async work is done by Huey, defined in api/background.py.

    Services (api/services/)¶

    Service file Responsibility
    notification_service.py Orchestrates all notification sending (email + push + Telegram)
    push_notifications.py FCM push notification delivery
    email_notifications.py SMTP email composition and delivery
    telegram_notifications.py Telegram bot messages
    store_notifications.py Saves NotificationLog records
    init_notifications.py Notification setup / initialization
    trip_registration_service.py Trip register / unregister / waitlist business rules
    upgrade_eligibility.py Checks if member is eligible for level upgrade
    auto_upgrade_service.py Automatic upgrade on logbook completion
    gallery_webhook.py Creates / updates / deletes galleries in the external media service
    global_settings.py Convenient access to ConfigurableSettings singleton
    here_maps_service.py Reverse geocoding with cache
    permission_service.py Permission-related helpers
    subscription.py Computed status/reason off paid_member + exempt groups (compute_status, compute_reason, gated_actions, gating_mode, assert_subscription_active)
    subscription_events.py Append-only SubscriptionPaymentEvent recording, manual grants/revokes (set_membership_paid, with an optional audit note), and grant_membership (sets paid_member=True on one-time-order capture, idempotent on order id)

    Reuse the existing service for a given concern before introducing a new one. If a new service is needed, name it <resource>_service.py and register it under api/services/__init__.py if you want it importable from api.services.

    Huey background tasks¶

    Huey runs as a separate Docker container (Dockerhuey) in production, consuming from Redis. In development (no DJANGO_SECRET_KEY), tasks run synchronously (immediate mode) — see gotchas.

    Define tasks in api/background.py. Enqueue them from inside a DB write path with transaction.on_commit(lambda: task(pk)) and pass primitive ids, not model instances — see gotchas.

    Task Trigger Retries
    send_trip_notification Trip published 2 retries, 5 min delay
    send_trip_approval_notification Trip approved / declined 2 retries, 5 min delay
    send_registration_from_waitlist_notification Member moved from waitlist 2 retries, 15 min delay
    send_removed_from_trip_registered_notification Member removed from trip 2 retries, 15 min delay
    send_removed_from_trip_waitlist_notification Member removed from waitlist 2 retries, 15 min delay
    send_upgrade_request_handled_notification Upgrade request approved / declined 2 retries, 5 min delay
    send_upgrade_request_created_notification New upgrade request 2 retries, 5 min delay
    send_club_news ClubNews status → APPROVED 2 retries, 5 min delay
    send_feedback_notification Feedback submitted 2 retries, 5 min delay
    send_new_trip_comment_notification_task New trip comment 2 retries, 5 min delay
    create_gallery_for_trip_task Trip approved 6 retries, 1 hr delay
    update_gallery_for_trip_task Trip edited 6 retries, 1 hr delay
    delete_gallery_for_trip_task Trip deleted 3 retries, 1 hr delay
    restore_gallery_for_trip_task Trip restored 3 retries, 1 hr delay

    Periodic tasks (cron)¶

    Schedule Task Action
    Daily 00:00 process_account_deletion_requests Anonymize members who requested deletion >3 days ago
    Daily 01:00 cleanup_expired_geocoding_cache Delete expired HERE Maps cache entries
    Daily 02:00 periodic_purge_inactive_devices Delete inactive FCM devices >30 days
    Daily 03:00 periodic_delete_old_triprequests Delete TripRequest rows older than yesterday
    Daily 04:00 periodic_purge_old_notifications Delete NotificationLog rows >60 days
    Daily 04:30 cleanup_blacklisted_tokens Delete BlacklistedToken rows whose underlying refresh has already expired
    Daily 04:45 cleanup_expired_outstanding_tokens Delete OutstandingToken rows whose refresh has expired (cascades blacklist rows)
    Daily 04:50 cleanup_handoff_tokens Delete consumed AppWebHandoffToken rows immediately; delete expired-but-never-consumed rows after a 7-day audit window
    Daily 20:00 periodic_upgrade_request_reminder Send upgrade request reminders
