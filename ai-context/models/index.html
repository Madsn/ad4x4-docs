    Data Models¶

    AI-context reference. Models live in api/models/ (one file per model group, registered in api/models/__init__.py). The website app contributes two singleton-style models. Always read AGENTS.md first for the gotchas that touch these models.

    api.Member — AUTHUSERMODEL¶

    Custom AbstractUser. Key fields: - username (unique, 50) - email (unique, 255) - phone (PhoneNumberField, AE region) - level (FK → Level) - trip_count - gender (M/F/O) - nationality (ISO 3166 code) - avatar (ImageField, max 2.5MB) - paid_member (bool, indexed) — authoritative lifetime-membership flag. One-time payment sets it True permanently; it drives the computed subscription status and all gating. No expiry or renewals — the rolling-subscription model was reverted (issue #169). - last_visited (DateTimeField, updated by LastVisitedMiddleware throttled 1/hr)

    Manager: MyUserManager — case-insensitive get_by_natural_key. Key method: anonymize_data() — GDPR deletion (deactivates, wipes PII, deletes vehicles). Level-group sync: enforced in api.signals.member_post_save via sync_member_level_groups(). Backfill command: python manage.py sync_member_level_groups.

    Level¶

    name, numeric_level (1–999), auto_group (FK → Group; auto-assigns users on upgrade), display_name, active, min_trips_for_upgrade.

    PermissionMatrix¶

    Group-based permission control. Fields: action (ActionChoice), group (FK → Group), levels (M2M → Level — empty means ALL levels, see gotchas). Unique on (action, group).

    Class method: PermissionMatrix.has_permission(user, action, member=None, trip=None, require_trip_lead=False) — the authoritative permission check. Always use this for authorisation logic.

    Trip¶

    lead (FK → Member, PROTECT), deputy_leads (M2M → Member), title, description, level (FK → Level, PROTECT), start_time, end_time, cut_off, meeting_point (FK → MeetingPoint), capacity, registered (M2M via TripRegistration), waitlist (M2M via TripWaitlist), approval_status (P/A/R/C), allow_waitlist, gallery_id (UUID string, links to external gallery service).

    TripRegistration / TripWaitlist¶

    Join tables with member, trip, vehicle (optional FK, SET_NULL on vehicle delete), registration_date, checked_in (TripRegistration only).

    Trip detail responses may also include overlap metadata on each registered[] row: hasOverlap and overlappingTrips. Those use the same overlap rules as the create/register/waitlist warnings and are intended for trip-lead roster review.

    TripRegistrationCancellationReason¶

    Audit record for lead/admin cancellation actions. Stores the affected member, trip, optional vehicle, cancellation reason, and whether the member came from registered or waitlist state. Notification tasks take this row's id, not model instances.

    TripComment / TripRating¶

    Trip discussion and rating records. TripComment drives comment notifications; TripRating stores member feedback for completed trips.

    TripRequest¶

    Member's trip wish: member, time_of_day (MOR/MID/AFT/EVE/ANY), area (DXB/NOR/AUH/AAN/LIW), level, date (max 16 days ahead). Auto-deleted after 1 day by periodic task.

    UpgradeRequest¶

    applicant (FK → Member, nullable — store username backup in applicant_str), target_level, status (N/I/A/D), yes_voters/no_voters/defer_voters/nominated_voters (all M2M → Member), final_approver, verdict_date, verdict_reason, attachment.

    Status flow: NEW → IN_PROGRESS → APPROVED/DECLINED. verdict_date auto-set in save().

    UpgradeRequestComment¶

    Comment thread on upgrade requests. Create/edit/delete actions are PermissionMatrix-gated separately from the parent request.

    LogbookSkill / LogbookSkillCategory¶

    Skills that can be verified on trips. name, description, active, level_requirement (FK → Level), order, count_requirement, category (FK → LogbookSkillCategory).

    LogbookEntry¶

    Trip attendance + skill record per member. trip, member, signed_by (marshal), skills_verified (M2M → LogbookSkill), comment. Unique per (member, trip) so migration approval reuses the same parent row instead of creating duplicates.

    LogbookSkillReference¶

    Granular join: member earned a specific skill on a specific trip. logbook_skill, member, trip, signed_by, entered_by, entered_at. Unique on (member, trip, logbook_skill) — preserves audit history (see gotchas).

    LogbookMigrationRequest¶

    Import logbook from old system. member, target_level, status (PENDING/APPROVED/RETURNED/REJECTED), migration_type (MEMBERINITIATED/MANAGERDIRECT), uploaded_pdf, rejection_reason, return_comment. Create-time validation rejects duplicate skill_entries.trip values with migration_skill_entries_duplicate_trip.

    LogbookMigrationSkillEntry¶

    Per-skill entry attached to a migration request. Records requested migrated skill evidence before approval.

    ClubNews¶

    Broadcast to members at specific levels. title, content, levels (M2M, empty=all), status (DRAFT→APPROVED→SENT/ERROR/DELETED), image. Editable at any status — save() sets submit_date only on the first transition into APPROVED (re-saving a published entry never rewrites it, and notifies exactly once on that first transition — see gotchas). Admin CRUD at /api/admin/clubnews/ (MANAGE_CLUB_NEWS); the public /api/clubnews/ stays read-only/SENT-only.

    NotificationLog¶

    Notification audit trail. member, title, body, timestamp, type (NotificationType), related_object_id, related_object_type, is_read. Purged after 60 days by a periodic task.

    GitHubWebhookDelivery¶

    Inbound GitHub webhook audit trail for private-repo PR notifications. Tracks delivery_id, repository, event_name, action, PR metadata, delivery status, payload, error, and timestamps.

    NotificationSettings¶

    Per-member notification preferences for email/push/Telegram-style delivery channels. Created alongside members and touched by the legacy auth side effect in JWTAuthentication.get_user().

    ConfigurableSettings (singleton)¶

    Global configuration. One record only — save() raises on duplicate. Includes: default user level/group, auto-upgrade rules, email addresses, email sleep period, notification dry-run toggle, HERE Maps config, gallery API config, vehicle limit per member, force_waitlist, trip edit cutoff minutes. Subscription fields (Django admin only, excluded from the API serializer): subscription_exempt_groups (M2M → Group), annual_subscription_price, annual_subscription_currency, gated_actions (JSON list of gated action keys — enforced + cosmetic — surfaced to clients), gating_mode (off/soft/hard, default off — soft reports unpaid without a 403, hard enforces it).

    Always access via ConfigurableSettings.objects.first() or the global_settings.py service. .objects.first() can return None in fresh dev/test environments where the row hasn't been seeded — guard for None or use the service.

    GeocodingCache¶

    HERE Maps response cache. Unique on (latitude, longitude). Has expires_at, increment_access(), cleanup_expired() class method. Periodic task cleans stale entries at 1 AM.

    Vehicle¶

    Member's vehicle. brand (74 CarBrand choices), model, year, color, image, is_primary. Limit enforced by vehicle_limit_per_member in ConfigurableSettings.

    AccountDeletionRequest¶

    3-day grace period model. Midnight periodic task calls member.anonymize_data() and deletes the request.

    Feedback¶

    Member feedback/contact submission with optional images and admin notification side effects.

    Sponsorship¶

    Sponsor directory entry with logo/image and ordering/display metadata.

    FaqEntry¶

    Public FAQ entry, ordered for client display.

    TripReport / TripReportImage¶

    Post-trip reports and their images. Trip reports are exposed as a nested trip resource and as a separate report list.

    UIString¶

    Admin-managed key/value strings used by clients for dynamic copy.

    PayPalConfiguration (website app, singleton)¶

    Payment config: sandbox_mode, is_active, payment_amount / payment_currency (PayPal-side, limited currency list), display_amount / display_currency (shown to user, AED). PayPal does NOT support AED — the club charges in USD (~27 USD) but shows 100 AED. See gotchas.

    WebsitePayment (website app)¶

    Transaction record: member, amount, currency, payment_method, paypal_order_id, paypal_transaction_id, payer_email, status (pending/completed/failed/refunded). This one-time-order flow IS the membership purchase — on capture it grants lifetime membership (sets paid_member=True) via grant_membership (see website/views.py + api/services/subscription_events.py).

    SubscriptionPaymentEvent (api, append-only)¶

    Immutable audit trail for membership payment events — the record for audit, member history, and treasurer export. Fields: member, event_type (paymentcompleted / manualgrant / comp / refund), source (paypal / manual_admin / migration), paypal_event_id (unique idempotency key — the PayPal order/capture id), amount, currency, payer_email, period_end_after_event (unused in the lifetime model; retained for the audit-row schema), created_by, note (free-text reason for a manual grant/comp/revoke), raw_payload, occurred_at. Registered read-only in Django admin with a CSV export action.

    Membership is a one-time lifetime payment (pay once → paid_member=True permanently). The rolling 12-month subscription model was reverted (issue #169).

    KitItem / KitEntitlement (api/models/models_kit.py)¶

    KitItem — a physical kit item: name (unique), is_active, cost (decimal), timestamps. KitEntitlement — OneToOne → KitItem with a quantity (default 1), defining how many of that item a member is entitled to. Managed via /api/kit-items/ and /api/kit-entitlements/.

    Kit voucher / inventory (api/models/models_kit_voucher.py)¶

    The kit-distribution + marshal-stock audit stack.

    • KitVoucher — OneToOne → Member; a member's voucher bundle. Spawns KitVoucherLine rows per entitled item.
    • KitVoucherLine — one item line: voucher (FK), item (FK → KitItem), quantity, quantity_collected, status (KitVoucherLineStatus), collected_by_marshal, collected_at.
    • KitVoucherToken — single-use redemption token sent to the member: voucher (FK), token_hash (unique), short_code (unique), expires_at, used_at.
    • MarshalStockEvent — append-only audit row for marshal stock movements: marshal (FK), item (FK), type (MarshalStockEventType: STOCK_GIVEN / ADJUST / ISSUE), qty, note, recipient (FK → Member, nullable — the member an ISSUE went to, added in #214), created_by (FK, nullable), created_at. On-hand is derived (stock_given + adjust − issued), never stored.

    AppWebHandoffToken¶

    Single-use, short-TTL token that bridges an authenticated app session into a web session so the app → web pay/manage jump skips the system-browser login wall. Fields: token_hash (SHA-256 hex of the cleartext token — unique, indexed; cleartext is returned once on mint and never persisted), member (FK → Member), created_at, expires_at, used_at (set on exchange — single-use is enforced atomically via select_for_update()), source_ip (audit only). TTL is env-driven via HANDOFF_TOKEN_TTL_SECONDS (default 300s). Purged by the cleanup_handoff_tokens periodic task (consumed rows immediately; expired-but-unused after 7 days).
