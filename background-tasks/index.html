    Background Tasks¶

    The AD4x4 backend uses Huey (a lightweight task queue) for asynchronous background processing. Background tasks handle operations that should not block HTTP requests, such as:

    • Sending notifications (push, email, Telegram)
    • Syncing with external services (Gallery system)
    • Periodic cleanup operations
    • Delayed processing

    Architecture¶

    Huey Configuration¶

    Huey is configured in ad4x4/settings.py:

    HUEY = {
    'huey_class': 'huey.RedisHuey',
    'connection': {
        'host': os.getenv('REDIS_HOST'),
        'port': os.getenv('REDIS_PORT'),
        'password': os.getenv('REDIS_PASSWORD'),
    },
    'consumer': {
        'workers': 1,
        'worker_type': 'thread',
        'scheduler_interval': 1,
        'periodic': True,
    },
}

    Task Types¶

    Decorator Use Case Example
    @task One-time async task Sending a notification
    @periodic_task Scheduled recurring task Daily cleanup at 3 AM

    Running the Task Consumer¶

    The Huey consumer must be running for background tasks to execute:

    python manage.py run_huey

    Important: This command blocks and runs continuously. Run it in a terminal, supervisor, or systemd service.

    Consumer Options¶

    python manage.py run_huey \
  --worker-type=thread \      # or 'process'
  --workers=2 \               # number of workers
  --scheduler_interval=1      # scheduler check interval (seconds)

    Task Trigger Retry Policy
    create_gallery_for_trip_task Trip approval 6 retries, 1hr delay
    update_gallery_for_trip_task Trip update 6 retries, 1hr delay
    delete_gallery_for_trip_task Trip deletion (soft) 3 retries, 1hr delay
    restore_gallery_for_trip_task Trip restoration 3 retries, 1hr delay

    Periodic Cleanup Tasks¶

    Task Schedule Description
    periodic_purge_old_notifications Daily at 4 AM Deletes notification logs older than 60 days
    periodic_purge_inactive_devices Daily at 2 AM Removes inactive FCM devices (30+ days old)
    periodic_delete_old_triprequests Daily at 3 AM Deletes trip requests older than 1 day
    process_account_deletion_requests Daily at 12 AM Processes accounts pending deletion after 3-day grace period
    cleanup_expired_geocoding_cache Daily at 1 AM Removes expired geocoding cache entries

    Scheduling Syntax¶

    Cron Expressions¶

    Tasks use crontab-style scheduling:

    @periodic_task(crontab(minute='0', hour='20'))
def daily_reminder():
    pass

    Crontab Parameters: | Parameter | Values | |-----------|--------| | minute | 0-59 or '' | | hour | 0-23 or '' | | day | 1-31 or '' | | month | 1-12 or '' | | day_of_week | 0-6 (Monday-Sunday) or '*' |

    Examples¶

    # Every day at 8 PM
@periodic_task(crontab(minute='0', hour='20'))

# Every hour at minute 30
@periodic_task(crontab(minute='30', hour='*'))

# Every Monday at 9 AM
@periodic_task(crontab(minute='0', hour='9', day_of_week='1'))

# Every 15 minutes
@periodic_task(crontab(minute='*/15'))

    Error Handling¶

    Retry Configuration¶

    Tasks can be configured with retries:

    @task(retries=3, retry_delay=3600)  # 3 retries, 1 hour between
def fragile_task(data):
    pass

    Retry Parameters: | Parameter | Description | |-----------|-------------| | retries | Maximum retry attempts (default: varies) | | retry_delay | Seconds to wait between retries (default: varies) |

    Logging¶

    All background task logging goes to the ad4x4-worker logger:

    import logging
logger = logging.getLogger('ad4x4-worker')

logger.info(f'Processing {count} items')
logger.error(f'Failed to process: {str(e)}')

    Monitoring¶

    Check task execution in: 1. Application logs 2. Django admin (failed task records) 3. Redis (task queue status)

    Debugging Tips¶

    List Pending Tasks¶

    # In Django shell
from huey.contrib.djhuey import huey
print(huey.pending())  # Returns pending task count

    Run Task Immediately¶

    from api.background import send_trip_notification
send_trip_notification(trip)  # Schedules async execution

    Test Task Synchronously¶

    For testing, tasks can be executed synchronously by setting immediate=True in settings or using huey's testing mode.

    Troubleshooting¶

    Consumer Not Running¶

    Symptom: Notifications not sent, galleries not created Fix: Start the consumer: python manage.py run_huey

    Tasks Stuck in Queue¶

    Symptom: Tasks accumulating, not processing Fix: Check Redis connection and consumer logs

    Task Failures¶

    Symptptom: Same task failing repeatedly Fix: Check logs for error details; fix underlying issue; manually retry

    High Memory Usage¶

    Symptom: Worker consuming too much memory Fix: Reduce workers count or use process worker type instead of thread
