    Maintenance Mode¶

    Maintenance mode allows administrators to temporarily take the API offline for updates, migrations, or emergency repairs. During maintenance, all API requests receive a 503 Service Unavailable response.

    How It Works¶

    Client Request
    ↓
Maintenance Mode Check
    ↓
Enabled → Return 503 Service Unavailable
Disabled → Continue normal processing

    Enabling Maintenance Mode¶

    Maintenance mode is controlled via Global Settings in the admin panel:

    Setting Description
    maintenance_mode_enabled Master switch for maintenance mode

    When enabled, the API returns:

    {
    "success": false,
    "message": "maintenance_mode_enabled"
}

    HTTP Status: 503 Service Unavailable

    Client-Side Handling¶

    Client applications should implement the following:

    1. Detect Maintenance Response¶

    if (response.status === 503 && response.data.message === 'maintenance_mode_enabled') {
    // Show maintenance screen
}

    2. User Notification¶

    Display a friendly message:

    "The AD4x4 app is currently undergoing scheduled maintenance. Please try again in a few minutes."

    3. Retry Strategy¶

    Attempt Wait Time
    1 30 seconds
    2 1 minute
    3 2 minutes
    4+ 5 minutes (max)

    Do not implement aggressive retry loops as this will overload the server.

    4. Offline Support¶

    Consider caching essential data for users who open the app during maintenance: - Cached trips - Cached member profiles - Offline queue for pending actions

    Common Use Cases¶

    Planned Maintenance¶

    1. Announce maintenance window in advance (Club News, notifications)
    2. Enable maintenance mode at scheduled start time
    3. Perform required work
    4. Disable maintenance mode after completion
    5. Notify users maintenance is complete

    Emergency Maintenance¶

    1. Enable maintenance mode immediately
    2. Address the emergency issue
    3. Disable maintenance mode when resolved
    4. Post-explanation in Club News

    Database Migrations¶

    Some migrations require brief maintenance windows: - Schema changes - Data migrations - Index creation

    Monitoring¶

    During maintenance mode, monitor:

    1. Server logs - Check for unexpected errors
    2. Redis queue - Ensure Huey tasks are processing
    3. Client traffic - Verify 503 responses are returned

    Best Practices¶

    Communication¶

    • Use Club News to announce planned maintenance
    • Include expected duration
    • Provide contact information for issues

    Scheduling¶

    • Schedule during low-traffic hours (early morning)
    • Keep maintenance windows short
    • Have rollback plan ready

    Testing¶

    Test maintenance mode before relying on it:

    # In Django admin or shell
from api.services.global_settings import set_maintenance_mode
set_maintenance_mode(True)

    Troubleshooting¶

    Maintenance Mode Not Working¶

    Symptom: API still responding normally Causes: - Setting not saved - Cache not invalidated - Wrong middleware order Fix: Verify setting in admin, clear cache, check middleware

    Clients Still Making Requests¶

    Symptom: High traffic during maintenance Causes: - Aggressive client retry logic - Users refreshing manually Fix: Push notification to inform users, implement client-side blocking
