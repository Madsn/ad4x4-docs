    Authentication and Profiles¶

    This document outlines the API endpoints for user authentication, registration, and profile management.

    For a high-level overview of the authentication process, please refer to the API Concepts document.

    Registration and Password Management¶

    The API provides endpoints for user registration and password management, powered by the rest_registration library.

    Registration¶

    POST /api/auth/register/

    The request body should include the user's details as defined by the MemberRegistrationSerializer.

    Request Body:

    {
    "username": "newuser",
    "email": "user@example.com",
    "firstName": "John",
    "lastName": "Doe",
    "phone": "0501234567",
    "password": "securePassword123",
    "password2": "securePassword123",
    "dob": "1990-01-15",
    "iceName": "Jane Doe",
    "icePhone": "0507654321",
    "gender": "M",
    "nationality": "AE",
    "city": "Dubai",
    "carBrand": "TO",
    "carModel": "Land Cruiser",
    "carColor": "White",
    "carYear": 2022
}

    Fields:

    Field Type Required Description
    username string Yes Unique username
    email string Yes Email address
    firstName string No First name
    lastName string No Last name
    phone string No Phone number
    password string Yes Password
    password2 string Yes Password confirmation (must match password)
    dob date No Date of birth (YYYY-MM-DD)
    iceName string No Emergency contact name
    icePhone string No Emergency contact phone
    gender string No Gender code (M, F, O)
    nationality string No Country code (e.g., "AE")
    city string No City name
    avatar file No Profile image (multipart/form-data)
    carBrand string No 2-letter car brand code (e.g., "TO" for Toyota). If provided, a Vehicle is automatically created.
    carModel string No Car model name
    carColor string No Car color
    carYear integer No Car year of manufacture

    Note: The carBrand, carModel, carColor, and carYear fields are write-only. When provided during registration, a Vehicle record is automatically created and set as the member's primary vehicle. See Vehicles for managing vehicles after registration.

    Note: When REGISTER_VERIFICATION_ENABLED is on, newly registered members are created inactive (is_active=False) and must verify their email address before they can log in. Login attempts for an inactive account return email_not_verified until verification completes.

    Change Password¶

    Authenticated users can change their password by making a POST request to /api/auth/change-password/.

    POST /api/auth/change-password/

    Request Body:

    {
    "oldPassword": "current_password",
    "password": "new_password",
    "passwordConfirm": "new_password"
}

    Fields:

    Field Type Required Description
    oldPassword string Yes Current password
    password string Yes New password
    passwordConfirm string Yes New password confirmation (must match password)

    Note: The API accepts camelCase field names. The underlying serializer fields are old_password, password, and password_confirm.

    Note: password and passwordConfirm must match.

    Important: When a user changes their password, every outstanding refresh token for the user is blacklisted — including the refresh token belonging to the device that just changed the password. Every device must log in again with the new password to obtain a fresh token pair. This is intentional: a password change may follow a suspected credential leak, so we invalidate every active session. Clients should clear their stored tokens immediately after a successful change-password response and route the user to the login screen.

    Other Endpoints¶

    The rest_registration library also provides endpoints for: * Resetting a forgotten password * Verifying registration via email

    Please refer to the library's documentation for details on these flows.

    Login, Logout, and Session Management¶

    Login and session management are covered in detail in API Concepts → Authentication. Quick summary of the endpoints:

    Endpoint Description
    POST /api/auth/login/ Log in with login (username or email) + password. Returns an access + refresh token pair wrapped in the unified envelope.
    POST /api/token/ Alias for /api/auth/login/ with the same request/response shape.
    POST /api/token/refresh/ Exchange a refresh token for a new {access, refresh} pair. Refresh tokens rotate: the old refresh token is blacklisted on use, so always store whichever refresh token the response hands back.
    POST /api/auth/logout/ Body: {"refresh": "<this device's refresh token>"}. Blacklists only that one session; other devices keep working. Idempotent.
    POST /api/auth/logout-all/ Blacklists every outstanding refresh token for the user, including the current one. All devices must re-login.
    GET /api/auth/sessions/ Lists the authenticated user's active refresh-token sessions (jti, createdAt, expiresAt — never the raw token). Useful for a "manage devices" UI.
    DELETE /api/auth/sessions/ Body: {"keep_refresh": "<current session refresh token>"}. Blacklists every session except the one whose refresh token is supplied. Omit keep_refresh to blacklist everything (equivalent to logout-all).

    Token lifetimes default to 24 hours (access) and 30 days (refresh), configurable via the ACCESS_TOKEN_MINUTES and REFRESH_TOKEN_DAYS environment variables.

    Profile Management¶

    Retrieving a Profile¶

    To retrieve a user's profile, make a GET request to /api/members/{id}/.

    GET /api/members/{id}/

    Success Response: The response will be a JSON object containing the user's profile information. The fields returned are defined by the ProfileSerializer.

    Note: While the serializer and database use snake_case for field names (e.g., first_name), the API will return camelCase in the response body (e.g., firstName).

    {
    "id": 1,
    "username": "testuser",
    "email": "test@example.com",
    "firstName": "Test",
    "lastName": "User",
    "phone": "1234567890",
    "dob": "2000-01-01",
    "iceName": "Jane Doe",
    "icePhone": "0987654321",
    "level": {
        "id": 1,
        "name": "Newbie",
        "numericLevel": 10,
        "minTripsForUpgrade": 5
    },
    "tripCount": 5,
    "avatar": null,
    "permissions": [
        {
            "id": 1,
            "action": "search_members",
            "levels": []
        }
    ],
    "paidMember": true,
    "dateJoined": "2026-01-01T12:00:00",
    "city": "Dubai",
    "gender": "M",
    "nationality": "AE",
    "title": "",
    "lastVisited": "2026-03-30T14:22:00Z"
}

    Note: The profile response does NOT include vehicle/car fields. Vehicles are managed separately via the Vehicles endpoints.

    Note on permissions: Each entry has an action field containing the lowercase DB value of the action (e.g., "search_members", "create_trip"). The levels field contains an array of level objects ({id, name, numericLevel, minTripsForUpgrade}) for permissions that are restricted to specific levels. An empty levels array means the permission applies to all levels.

    Updating a Profile¶

    To update a user's profile, make a PATCH request to /api/members/{id}/. Users can only update their own profiles unless they are an administrator.

    PATCH /api/members/{id}/

    Request Body: The request body should contain the fields to be updated. Note that some fields like username, email, level, tripCount, paidMember, and lastVisited are read-only.

    Editable Fields: firstName, lastName, phone, city, dob, iceName, icePhone, gender, nationality, avatar, title

    Success Response: A successful update will return a 200 OK status code and the updated profile data.

    Firebase Custom Token¶

    Generate Firebase Custom Token¶

    • POST /api/firebase/custom-token

      Note: This endpoint does NOT use a trailing slash.

      • Generates a Firebase custom authentication token for the authenticated user. This can be used by clients to authenticate with Firebase services (e.g., real-time database, Cloud Messaging).
      • Authentication: Required (Bearer token).

    Example Request:

    curl -X POST "http://localhost:8000/api/firebase/custom-token" \
  -H "Authorization: Bearer <your-token>"

    Success Response (200 OK):

    {
    "firebaseToken": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 3600
}
    Field Type Description
    firebaseToken string Firebase custom token (JWT)
    expiresIn integer Token expiry in seconds (3600 = 1 hour)

    Error Response (500 Internal Server Error):

    {
    "detail": "Firebase error: <error_message>"
}

    This error occurs if the Firebase Admin SDK is not initialized or encounters an error during token creation.
