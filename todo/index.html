    This document contains notes on things that are missing or need to be improved for the documentation. The docs are markdown files under the "docs" folder, and are automatically pushed to a github pages site. Docs are generated from the markdown using https://squidfunk.github.io/mkdocs-material/ The menu/page organization is specified in the mkdocs.yml file.

    • Home and Getting started pages are currently blank. Suggest reorganizing so everything nested under "documentation" is brought to the top level of menu, get rid of "getting started" and populate the home page with a general overview of the API.
    • We need to add a page that covers use of swagger docs, links to the swagger docs page and explains how to get the bearer token and use it in swagger.
    • UI Strings page validation rules are poorly phrased. Define those in a more formal way.
    • Notifications page is missing a list or table of the NotificationType enum values
    • On the Upgrade Requests page, the "Create an Upgrade Request" section mentions targetlevel and applicantreason etc., but while the fields are snake_case in the serializer, they are actually camelCase in the API. Need to clarify that.
    • Check other pages for snake_case vs camelCase inconsistencies in field names.
    • The Permissions, Groups and Levels page should cover how to fetch the permissions for a user via the API.
    • Add a page for Maintenance mode (503 errors returned for all clients when enabled, clients must handle this and show proper error messages)
    • Add a page for Rate limiting - document how the rate limiting is configured for nginx (default.conf.template), and that the clients will receive HTTP 429 - and should show appropriate error messages to the user if they hit that limit.
    • Trips page does not cover deletion of trips
    • Need to add a page for the digital logbook and signing of logbooks. Link to this page from the Trips page.
