    Digital Logbook¶

    The digital logbook allows members to track their progress and have their skills verified by trip leads.

    Endpoints¶

    Create a Logbook Entry¶

    • POST /api/trips/{id}/logbook-entries
      • Creates a new logbook entry for a trip.
      • Requires CREATE_LOGBOOK_ENTRIES or CREATE_LOGBOOK_ENTRIES_SUPERUSER permission.

    View Logbook Entries for a Trip¶

    • GET /api/trips/{id}/viewlogbooks
      • Retrieves a list of members checked in to a trip, along with their associated logbook entry.

    View Logbook Entries for a Member¶

    • GET /api/members/{id}/logbookentries
      • Retrieves a list of logbook entries for a specific member.

    List Logbook Skills¶

    • GET /api/logbookskills
      • Retrieves a list of all available logbook skills.
      • The count_requirement field indicates the minimum number of sign-offs required for a skill.
      • The category field is an object containing the ID and name of the skill category.
      • Skills can be filtered by category using the category query parameter (e.g., /api/logbookskills?category=1).

    Logbook Entry Permissions¶

    Creating, updating, and deleting logbook entries is governed by a detailed permission system. The rules are as follows:

    Members Creating Entries for Themselves¶

    • A member cannot create, update, or delete a logbook entry for themselves.
    • Exception: A member with the CREATE_LOGBOOK_ENTRIES_SUPERUSER permission can create, update, or delete an entry for themselves, provided they are registered for the trip.

    Members Creating Entries for Other Members¶

    • Trip Lead or Deputy Lead: A trip lead or deputy lead can create, update, or delete a logbook entry for another member, provided that the other member is registered for the trip. The lead/deputy lead does not need to be registered themselves.
    • Superuser (CREATE_LOGBOOK_ENTRIES_SUPERUSER): A member with this permission can create, update, or delete a logbook entry for another member, provided that the other member is registered for the trip.
    • Regular Member (with CREATE_LOGBOOK_ENTRIES permission): A regular member can create, update, or delete a logbook entry for another member if all of the following conditions are met:
    • The acting member is registered for the trip.
    • The other member is registered for the trip.
    • The acting member has the CREATE_LOGBOOK_ENTRIES permission that applies to the trip's level.

    Skill Sign-Off Validation (when skills_verified are included in the request)¶

    A user can sign off on skills for another user if any of the following are true:

    • They are the Trip Lead or Deputy Lead for the associated trip.
    • They have the SIGN_LOGBOOK_SKILLS permission AND are registered for the associated trip themselves.
    • They have the CREATE_LOGBOOK_ENTRIES_SUPERUSER permission (this permission bypasses all other skill sign-off checks).

    If a user has permission to create or update a logbook entry but lacks the required skill sign-off permissions, the entire request will be denied if it includes skills_verified.

    Auto-Upgrade on First Logbook Entry¶

    When enabled via Global Settings, members can be automatically upgraded to the next level after their first logbook entry is created.

    How It Works¶

    1. A logbook entry is created for a member
    2. The system checks if:
    3. Auto-upgrade is enabled in global settings
    4. The member is at the configured source_level
    5. If conditions are met, the member is automatically upgraded to the target_level
    6. The member is also added to the target level's auto_group (if configured)

    Reverting Upgrade¶

    If a logbook entry is deleted and it was the member's only logbook entry, the upgrade is automatically reverted: 1. The system detects the deletion 2. Checks if the member has any remaining logbook entries 3. If no entries remain, the member is reverted to the source_level 4. The member is removed from the target level's auto_group (if different from source)

    Configuration¶

    See Global Settings for configuration details.
