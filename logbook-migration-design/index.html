    Logbook Migration - Design Document¶

    Overview¶

    NOTE: This has not yet been implemented.

    This document outlines the backend design for migrating from paper-based logbooks to digital logbooks. The system allows users who have already purchased paper logbooks to migrate their existing signatures and skills to the digital system.

    Use Cases¶

    1. Member-Initiated Migration¶

    Any member can submit a migration request to transfer skills from their physical logbook to the digital system. This includes: - Non-paid members (e.g., Newbie level): Can submit with empty skill_entries to become paid members upon approval - Paid members: Must include skill entries to migrate their skills

    2. Manager Direct Migration¶

    A trip manager (marshal with elevated permissions) can sit with a member physically and enter the data directly. This bypasses the review cycle - the request is approved immediately upon creation.

    Data Models¶

    Existing Models (Extended)¶

    LogbookSkillReference¶

    Extended with generic fields for migration audit trail:

    Field Type Description
    id BigAutoField Primary key
    logbook_skill ForeignKey (LogbookSkill) The skill being verified
    member ForeignKey (Member) Member whose skill is being verified
    trip ForeignKey (Trip) Trip where skill was verified
    signed_by ForeignKey (Member) Original signer (marshal/lead)
    entered_by ForeignKey (Member) NEW - Who entered into system (approver for migrations)
    entered_at DateTimeField NEW - When entered into system

    New Models¶

    LogbookMigrationRequest¶

    Field Type Constraints Description
    id BigAutoField PK Primary key
    member ForeignKey (Member) NOT NULL User submitting the request
    target_level ForeignKey (Level) NOT NULL The level being upgraded TO (e.g., Intermediate for Newbie-to-Intermediate)
    status CharField choices: PENDING, APPROVED, RETURNED, REJECTED Request status
    migration_type CharField choices: MEMBERINITIATED, MANAGERDIRECT Type of migration
    uploaded_pdf FileField nullable, maxlength=..., maxfile_size=3MB Uploaded PDF document
    rejection_reason TextField nullable Reason if rejected
    return_comment TextField nullable Comment when returned for amendments (accumulates)
    reviewed_by ForeignKey (Member) nullable Who reviewed the request
    reviewed_at DateTimeField nullable When was it reviewed
    created_at DateTimeField autonowadd Creation timestamp
    updated_at DateTimeField auto_now Last update timestamp

    Notes: - File upload path: logbook_migrations/{year}/{month}/{member_id}/{filename} - Status transitions: - PENDING → APPROVED (admin approves, skills created) - PENDING → RETURNED (admin sends back with comment) - PENDING → REJECTED (admin rejects with reason) - RETURNED → PENDING (member edits and resubmits) - For MANAGER_DIRECT: goes directly to APPROVED on creation

    LogbookMigrationSkillEntry¶

    Field Type Constraints Description
    id BigAutoField PK Primary key
    migration_request ForeignKey (LogbookMigrationRequest) NOT NULL, CASCADE Parent migration request
    trip ForeignKey (Trip) nullable Trip in system (if found)
    trip_description CharField max_length=200, nullable Fallback description if trip not in system
    signed_by ForeignKey (Member) nullable Marshal who signed in physical book (auto-populated from trip.lead, can be null)
    marshal_name CharField max_length=100, nullable Free-text marshal name from physical book (fallback if signed_by unknown)
    skills ManyToManyField (LogbookSkill) Skills/equipment claimed in this trip entry
    created_at DateTimeField autonowadd Entry creation timestamp

    Notes: - Either trip OR trip_description must be provided (not both null) - signed_by is nullable - auto-populated from trip.lead, but can be null if marshal unknown - Multiple skills can be claimed per trip entry

    API Endpoints¶

    Create Migration Request¶

    POST /api/logbook-migrations/

    Authentication: Required (Bearer token)

    Request Body (multipart/form-data):

    MEMBER_INITIATED type:

    {
  "migration_type": "MEMBER_INITIATED",
  "target_level": 4,
  "uploaded_pdf": <file>,
  "skill_entries": [
    {
      "trip": 123,
      "signed_by": 45,
      "marshal_name": "John Marshal",
      "skills": [1, 2, 3]
    },
    {
      "trip": 456,
      "signed_by": 67,
      "marshal_name": "Jane Lead",
      "skills": [4, 5]
    },
    {
      "trip_description": "Desert Trip - Jan 2024 (not in system)",
      "marshal_name": "Marshal Ali",
      "signed_by": null,
      "skills": [6]
    }
  ]
}

    MEMBER_INITIATED with no skills (non-paid member becoming paid):

    {
  "migration_type": "MEMBER_INITIATED",
  "target_level": 4,
  "uploaded_pdf": <file>,
  "skill_entries": []
}

    MANAGER_DIRECT type:

    {
  "migration_type": "MANAGER_DIRECT",
  "member": 789,
  "target_level": 4,
  "uploaded_pdf": <file, optional>,
  "skill_entries": [
    {
      "trip": 123,
      "signed_by": 45,
      "marshal_name": "Marshal Zour",
      "skills": [1, 2, 3, 4, 5, 6]
    }
  ]
}

    Response (201 Created):

    {
  "success": true,
  "message": {
    "id": 1,
    "member": 789,
    "targetLevel": { "id": 4, "name": "Intermediate", "numericLevel": 100 },
    "status": "PENDING",
    "migrationType": "MEMBER_INITIATED",
    "uploadedPdf": "/media/logbook_migrations/2026/03/123_abc.pdf",
    "skillEntries": [...],
    "createdAt": "2026-03-09T10:00:00.000Z"
  }
}

    Validation: - target_level must be valid and appropriate for the member's current level - For MEMBER_INITIATED: at least one skill entry required if member is already paid - For MANAGER_DIRECT: member field required + at least one skill entry - PDF max size: 3MB, type: application/pdf - Skills in entries must belong to the target level (or the level below for equipment) - Prevent duplicate submissions: don't allow a new PENDING request for the same member + target_level if one already exists

    Special behavior for MANAGER_DIRECT: - Status is set to APPROVED immediately - reviewed_by = the trip manager - reviewed_at = now - LogbookEntry and LogbookSkillReference records created immediately

    List Migration Requests¶

    GET /api/logbook-migrations/

    Authentication: Required

    Query Parameters: - status - Filter: PENDING, APPROVED, RETURNED, REJECTED - migration_type - Filter: MEMBERINITIATED, MANAGERDIRECT - member - Filter by member ID (admin only) - target_level - Filter by target level ID - page, pageSize - Pagination

    Regular user: sees only their own requests. Admin/Marshal with APPROVELOGBOOKMIGRATION permission: sees all requests.

    Response:

    {
  "count": 5,
  "results": [
    {
      "id": 1,
      "member": {
        "id": 123,
        "username": "johndoe",
        "firstName": "John",
        "lastName": "Doe"
      },
      "targetLevel": { "id": 4, "name": "Intermediate" },
      "status": "PENDING",
      "migrationType": "MEMBER_INITIATED",
      "uploadedPdf": "/media/logbook_migrations/2026/03/123_abc.pdf",
      "skillEntries": [...],
      "createdAt": "2026-03-09T10:00:00.000Z"
    }
  ]
}

    Approve Migration Request¶

    PATCH /api/logbook-migrations/{id}/approve/

    Authentication: Required

    Permissions: APPROVELOGBOOKMIGRATION

    Request Body (optional — admin can modify entries before approving):

    {
  "skill_entries": [
    {
      "id": 1,
      "trip": 45,
      "signed_by": 67,
      "skills": [1, 2]
    }
  ]
}

    Response (200 OK):

    {
  "success": true,
  "message": "Migration approved successfully. X skill references created, Y duplicates skipped."
}

    On Approval Processing:

    1. If member is not paid, set member's paid_member to True

    2. Backfill trip registrations — For each skill entry with a trip:

    3. Check if member is registered for that trip

    4. If NOT registered: call forceRegisterMember(tripId, memberId) internally

    5. Create LogbookEntry records — For each skill entry:

    6. Create one LogbookEntry with:

      • member = the migrating member
      • trip = the trip from the entry
      • signedBy = signed_by from the entry (or the reviewer if signed_by is null)
      • skillsVerified = the skill IDs from the entry
      • comment = "Migrated from physical logbook (Migration Request #{id})"

    7. Create LogbookSkillReference records — For each skill in each entry:

    8. Check for duplicates first: Skip if a reference already exists for member + logbookSkill + trip

    9. Create LogbookSkillReference with:

      • member = the migrating member
      • logbookSkill = the skill ID
      • trip = the trip from the entry
      • signed_by = the original marshal from the physical book (from entry's signed_by)
      • entered_by = the reviewer/approver
      • entered_at = now

    10. Update request status:

    11. status = APPROVED
    12. reviewed_by = the approver
    13. reviewed_at = now

    Return Migration Request for Amendments¶

    PATCH /api/logbook-migrations/{id}/return/

    Authentication: Required

    Permissions: APPROVELOGBOOKMIGRATION

    Request Body:

    {
  "return_comment": "Skills 3 and 5 are not visible in the PDF scan on page 2. Please upload clearer images or correct the claimed skills."
}

    Processing: - Set status = RETURNED - Append return_comment (keep history of all return comments) - Set reviewed_by = reviewer, reviewed_at = now

    Response (200 OK):

    {
  "success": true,
  "message": "Migration returned for amendments"
}

    Reject Migration Request¶

    PATCH /api/logbook-migrations/{id}/reject/

    Authentication: Required

    Permissions: APPROVELOGBOOKMIGRATION

    Request Body:

    {
  "rejection_reason": "The PDF appears to belong to a different member. Please verify and submit a new request."
}

    Response (200 OK):

    {
  "success": true,
  "message": "Migration rejected"
}

    Edit and Resubmit (Member, after RETURNED)¶

    PUT /api/logbook-migrations/{id}/

    Authentication: Required (must be the request owner)

    Conditions: Only allowed when status = RETURNED

    Request Body: Same structure as creation (can update skill_entries, upload new PDF)

    Processing: - Update skill entries (replace all) - Update PDF if new one provided - Set status = PENDING (back into review queue) - Clear reviewed_by, reviewed_at (fresh review)

    Permissions¶

    Permission Who What
    (authenticated) Any member Create own migration request, view own requests, edit own RETURNED requests
    APPROVELOGBOOKMIGRATION Marshals/Admins View all requests, approve/return/reject, download PDFs
    APPROVELOGBOOKMIGRATION + Trip Manager role Trip Managers All of the above + create MANAGER_DIRECT requests for any member

    Validation Rules¶

    1. PDF Upload:
    2. Max file size: 3MB
    3. Allowed types: application/pdf

    4. File path: logbook_migrations/{year}/{month}/{member_id}/{uuid_filename}.pdf

    5. Skill Entries:

    6. Each entry must have either trip (FK) OR trip_description (text), not both null
    7. At least one skill must be selected per entry
    8. For paid members: at least one skill entry required

    9. For non-paid members: skill_entries can be empty (becoming paid only)

    10. Target Level:

    11. Must be a valid level appropriate for the member's current level progression

    12. Duplicate Prevention:

    13. Cannot create new PENDING request for same member + target_level if one exists

    14. On approval, skip (don't fail) if member + logbookSkill + trip combo already exists

    15. Approval:

    16. Only PENDING requests can be approved/returned/rejected

    17. Approver cannot approve their own MEMBER_INITIATED request

    18. Skills:

    19. Skills must belong to target level (or the corresponding equipment level)

    Edge Cases¶

    1. User deletes vehicle while request pending:

    2. Allow (request stays pending)

    3. User deletes vehicle after skills migrated:

    4. Protected (PROTECT) - skills remain

    5. Trip deleted after migration:

    6. Keep reference (no CASCADE)

    7. Member deleted after migration:

    8. Keep LogbookEntry and LogbookSkillReference (no CASCADE)

    9. Approver approves their own request:

    10. Not allowed for MEMBER_INITIATED

    11. Marshal not found in system:

    12. Allow marshal_name free-text entry

    13. Admin can try to match to system member during review

    14. Trip not in system:

    15. Allow trip_description as fallback (no limit on usage)

    Admin Interface¶

    Pending Migrations Dashboard¶

    • List all PENDING requests
    • Filter by migrationtype, targetlevel
    • Show member info, upload date, type, target level
    • Quick actions: Approve, Return, Reject

    Review Screen¶

    • Display uploaded PDF
    • Show claimed trips/skills
    • Form to modify/verify skills before approval
    • For RETURNED requests: show accumulated return comments
    • Approve/Return/Reject buttons

    Integration Points¶

    Existing Systems¶

    1. Member Model:

    2. paid_member field updated if member is not paid on approval

    3. LogbookEntry:

    4. Created for each skill entry on approval

    5. LogbookSkillReference:

    6. Extended with enteredby, enteredat fields

    7. Trip Registration:

    8. forceRegisterMember called if member not registered for trip

    9. Notifications:

    10. Send notification when request approved/returned/rejected
    11. Notify approvers of new pending requests

    Migration Notes¶

    Database Migration Steps¶

    1. Add entered_by (FK to Member, nullable) to LogbookSkillReference
    2. Add entered_at (DateTimeField, nullable) to LogbookSkillReference
    3. Create LogbookMigrationRequest table
    4. Create LogbookMigrationSkillEntry table (with M2M to LogbookSkill)
    5. Add APPROVE_LOGBOOK_MIGRATION permission to the permission matrix

    Future Enhancements (Out of Scope)¶

    1. PDF parsing: Auto-extract skills from PDF (future)
    2. Multiple uploads: Support incremental skill migration
    3. Audit trail: Full history of approval actions
