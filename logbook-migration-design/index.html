    Logbook Migration - Design Document¶

    Overview¶

    NOTE: This has not yet been implemented.

    This document outlines the backend design for migrating from paper-based logbooks to digital logbooks. The system allows users who have already purchased paper logbooks to migrate their existing signatures and skills to the digital system.

    Use Cases¶

    1. New Member Migration (NEW_MEMBER)¶

    Users who have purchased a logbook but have not yet been upgraded to paid member can upload their logbook PDF to prove completion. Upon approval, they become paid members.

    2. Skill Migration (SKILL_MIGRATION)¶

    Existing paid members who have skills signed off in their paper logbook can upload their logbook and specify which trips and skills they claim. Upon approval, these skills are added to their digital logbook and count toward upgrade eligibility.

    Data Models¶

    Existing Models (Extended)¶

    LogbookSkillReference¶

    Extended with generic fields for future admin use (signing on behalf of marshals):

    Field Type Description
    id BigAutoField Primary key
    logbook_skill ForeignKey (LogbookSkill) The skill being verified
    member ForeignKey (Member) Member whose skill is being verified
    trip ForeignKey (Trip) Trip where skill was verified
    signed_by ForeignKey (Member) Original signer (marshal/lead)
    entered_by ForeignKey (Member) NEW - Who entered into system
    entered_at DateTimeField NEW - When entered into system

    New Models¶

    LogbookMigrationRequest¶

    Field Type Constraints Description
    id BigAutoField PK Primary key
    member ForeignKey (Member) NOT NULL User submitting the request
    status CharField choices: PENDING, APPROVED, REJECTED Request status
    migration_type CharField choices: NEWMEMBER, SKILLMIGRATION Type of migration
    uploaded_pdf FileField maxlength=..., maxfile_size=3MB Uploaded PDF document
    rejection_reason TextField nullable Reason if rejected
    reviewed_by ForeignKey (Member) nullable Who reviewed the request
    reviewed_at DateTimeField nullable When was it reviewed
    created_at DateTimeField autonowadd Creation timestamp
    updated_at DateTimeField auto_now Last update timestamp

    Notes: - File upload path: logbook_migrations/{year}/{month}/{member_id}/{filename} - Status transitions: PENDING → APPROVED or PENDING → REJECTED

    LogbookMigrationSkillEntry¶

    Field Type Constraints Description
    id BigAutoField PK Primary key
    migration_request ForeignKey (LogbookMigrationRequest) NOT NULL Parent migration request
    trip ForeignKey (Trip) nullable Trip in system (if exists)
    trip_description CharField max_length=200, nullable Fallback if trip not in system
    marshal_name CharField max_length=100 Name of marshal who signed
    signed_by ForeignKey (Member) NOT NULL Original signer from paper logbook
    skills ManyToManyField (LogbookSkill) Skills claimed in this entry
    migrated_by ForeignKey (Member) NOT NULL Approver who entered
    migrated_at DateTimeField autonowadd When migration was approved

    Notes: - Either trip OR trip_description must be provided - Multiple skills can be claimed per trip entry

    API Endpoints¶

    Create Migration Request¶

    POST /api/logbook-migrations/

    Authentication: Required (Bearer token)

    Request Body (multipart/form-data):

    NEW_MEMBER type:

    {
  "migration_type": "NEW_MEMBER",
  "uploaded_pdf": <file>
}

    SKILL_MIGRATION type:

    {
  "migration_type": "SKILL_MIGRATION",
  "uploaded_pdf": <file>,
  "skill_entries": [
    {
      "trip": 123,
      "marshal_name": "John Marshal",
      "signed_by": 45,
      "skills": [1, 2, 3]
    },
    {
      "trip_description": "Desert Trip - Jan 2024",
      "marshal_name": "Jane Lead",
      "signed_by": 67,
      "skills": [4, 5]
    }
  ]
}

    Response (201 Created):

    {
  "success": true,
  "message": {
    "id": 1,
    "member": 123,
    "status": "PENDING",
    "migration_type": "SKILL_MIGRATION",
    "uploaded_pdf": "/media/logbook_migrations/2026/03/123_abc.pdf",
    "skill_entries": [...],
    "createdAt": "2026-03-09T10:00:00.000Z"
  }
}

    Validation: - User must have at least one vehicle registered (for SKILLMIGRATION) - PDF file size must not exceed 3MB - PDF must be a valid file type (pdf only) - For SKILLMIGRATION: user must select at least one skill entry

    List Migration Requests¶

    GET /api/logbook-migrations/

    Authentication: Required

    Query Parameters: - status - Filter by status (PENDING, APPROVED, REJECTED) - migration_type - Filter by type (NEWMEMBER, SKILLMIGRATION) - page - Page number

    Regular User Response:

    {
  "count": 2,
  "results": [
    {
      "id": 1,
      "status": "PENDING",
      "migrationType": "SKILL_MIGRATION",
      "createdAt": "2026-03-09T10:00:00.000Z"
    }
  ]
}

    Admin/Approver Response: (with APPROVELOGBOOKMIGRATION permission)

    {
  "count": 5,
  "results": [
    {
      "id": 1,
      "member": {
        "id": 123,
        "username": "johndoe",
        "firstName": "John",
        "lastName": "Doe"
      },
      "status": "PENDING",
      "migrationType": "SKILL_MIGRATION",
      "uploadedPdf": "/media/logbook_migrations/2026/03/123_abc.pdf",
      "skillEntries": [...],
      "createdAt": "2026-03-09T10:00:00.000Z"
    }
  ]
}

    Approve Migration Request¶

    PATCH /api/logbook-migrations/{id}/approve/

    Authentication: Required

    Permissions: APPROVELOGBOOKMIGRATION

    Request Body:

    {
  "skill_entries": [
    {
      "id": 1,
      "trip": 45,
      "skills": [1, 2]
    }
  ]
}

    Notes: - For SKILLMIGRATION: approver can modify/verify skills before approval - For NEWMEMBER: no request body needed

    Response (200 OK):

    {
  "success": true,
  "message": "Migration approved successfully"
}

    On Approval Processing:

    NEWMEMBER type: 1. Set member's paid_member to True 2. Set request status to APPROVED 3. Set reviewedby and reviewed_at

    SKILLMIGRATION type: 1. For each verified skill entry: - Create LogbookEntry (trip, member, signedby, skillsverified) - Create LogbookSkillReference for each skill: - signedby = original signer from paper - enteredby = migratedby (approver) - enteredat = migratedat (now) 2. Set request status to APPROVED 3. Set reviewedby and reviewedat

    Reject Migration Request¶

    PATCH /api/logbook-migrations/{id}/reject/

    Authentication: Required

    Permissions: APPROVELOGBOOKMIGRATION

    Request Body:

    {
  "rejection_reason": "PDF is illegible, please upload a clearer copy"
}

    Response (200 OK):

    {
  "success": true,
  "message": "Migration rejected"
}

    Permissions¶

    User Permissions¶

    Permission Description
    (authenticated) Can create migration request
    (authenticated) Can view own migration requests

    Admin Permissions¶

    Permission Description
    APPROVELOGBOOKMIGRATION Can approve/reject migration requests
    APPROVELOGBOOKMIGRATION Can view all migration requests
    APPROVELOGBOOKMIGRATION Can download uploaded PDFs

    Validation Rules¶

    1. PDF Upload:
    2. Max file size: 3MB
    3. Allowed types: application/pdf

    4. File path: logbook_migrations/{year}/{month}/{member_id}/{uuid_filename}.pdf

    5. Skill Entries (SKILL_MIGRATION):

    6. At least one skill entry required
    7. Each entry must have either trip OR trip_description
    8. At least one skill must be selected per entry

    9. User must have participated in the trip (must be in trip.registered)

    10. Approval:

    11. Only PENDING requests can be approved/rejected
    12. Approver cannot approve their own request
    13. For SKILL_MIGRATION: trip must exist in system (if trip provided)

    Edge Cases¶

    1. User deletes vehicle while request pending:

    2. Allow (request stays pending)

    3. User deletes vehicle after skills migrated:

    4. Protected (PROTECT) - skills remain

    5. Trip deleted after migration:

    6. Keep reference (no CASCADE)

    7. Member deleted after migration:

    8. Keep LogbookEntry and LogbookSkillReference (no CASCADE)

    9. Approver uploads PDF for themselves:

    10. Not allowed (self-approval)

    Admin Interface¶

    Pending Migrations Dashboard¶

    • List all PENDING requests
    • Filter by migration_type
    • Show member info, upload date, type
    • Quick actions: Approve, Reject

    Review Screen¶

    • Display uploaded PDF
    • For SKILL_MIGRATION: show claimed trips/skills
    • Form to modify/verify skills before approval
    • Approve/Reject buttons

    Integration Points¶

    Existing Systems¶

    1. Member Model:

    2. paid_member field updated on NEW_MEMBER approval

    3. LogbookEntry:

    4. Created for each skill entry on SKILL_MIGRATION approval

    5. LogbookSkillReference:

    6. Extended with enteredby, enteredat fields

    7. Notifications:

    8. Send notification when request approved/rejected
    9. Notify approvers of new pending requests

    Migration Notes¶

    Database Migration Steps¶

    1. Create LogbookMigrationRequest table
    2. Create LogbookMigrationSkillEntry table
    3. Add fields to LogbookSkillReference:
    4. entered_by (FK to Member, nullable)
    5. entered_at (DateTimeField, nullable)

    Future Enhancements (Out of Scope)¶

    1. Admin direct entry: Allow admins to sign off skills on behalf of marshals directly (using the new enteredby/enteredat fields)
    2. PDF parsing: Auto-extract skills from PDF (future)
    3. Multiple uploads: Support incremental skill migration
    4. Audit trail: Full history of approval actions
