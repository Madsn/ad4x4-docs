    Upgrade Requests¶

    This document outlines the API endpoints for managing level upgrade requests.

    Overview¶

    Members can request to be upgraded to a higher level. This process involves creating a request, which is then reviewed and voted on by authorized members (e.g., Marshals, Board Members).

    Endpoints¶

    List and Retrieve Upgrade Requests¶

    • GET /api/upgraderequests/
      • Retrieves a list of upgrade requests. Requires VIEW_UPGRADE_REQ permission.
    • GET /api/upgraderequests/{id}/
      • Retrieves the details of a single upgrade request.

    Voter fields — integer counts, not arrays: On both list and detail responses, yesVoters, noVoters, and deferVoters are returned as integer counts (the total number of members who voted yes/no/defer), not as arrays of member objects. nominatedVoters, however, IS returned as an array of member objects (the members who were nominated to vote on this request). Do not attempt to iterate yesVoters — use it as a number.

    Status transitions: A request starts at status=N (NEW). When the first vote is cast it transitions to I (IN_PROGRESS). Final decisions set it to A (APPROVED) or D (DECLINED). verdictDate is auto-populated when status moves to APPROVED or DECLINED.

    Get Member Upgrade Eligibility¶

    • GET /api/members/{id}/upgradeeligibility

      Note: This endpoint does NOT use a trailing slash.

      • Retrieves a detailed report on a member's eligibility for an upgrade to the next potential level. This report includes a breakdown of met/unmet requirements based on minimum trips at the current level and required logbook skills for the next level.
      • Authorization:
        • A member can view their own eligibility (when {id} matches request.user.id).
        • Members with the VIEW_UPGRADE_REQ permission can view the eligibility of any member.
        • Superusers can view any member's eligibility.

      • Response Structure (Example):

        Note: The backend builds the response in snake_case, but the camelCase middleware automatically converts the keys. The response you receive will use camelCase.

        json { "memberId": 1, "memberUsername": "testuser", "currentLevel": { "id": 1, "name": "Newbie", "numericLevel": 10 }, "nextPotentialLevel": { "id": 2, "name": "Intermediate", "numericLevel": 100 }, "upgradeRequirements": [ { "type": "min_trips", "name": "Minimum trips for current level", "requiredValue": 5, "currentValue": 3, "met": false, "description": "You need 5 trips at your current level (completed at this level).", "recentTripsAtLevel": [ { "tripId": 10, "title": "Desert Crossing", "startTime": "2026-01-15T09:00:00+04:00", "lead": {"id": 1, "username": "leader1"}, "level": {"id": 1, "name": "Newbie", "numericLevel": 10} }, { "tripId": 9, "title": "Mountain Trail", "startTime": "2025-12-20T08:00:00+04:00", "lead": {"id": 2, "username": "leader2"}, "level": {"id": 1, "name": "Newbie", "numericLevel": 10} } ] }, { "type": "logbook_skill", "skillId": 101, "skillName": "Basic Recovery", "requiredCount": 2, "currentCount": 1, "met": false, "description": "Complete 'Basic Recovery' 2 times.", "signatures": [ { "tripId": 15, "signedBy": {"id": 5, "username": "verifier_user"}, "signedDate": "2026-02-01T10:30:00+04:00" } ] }, { "type": "logbook_skill", "skillId": 102, "skillName": "Tyre Changing", "requiredCount": 1, "currentCount": 1, "met": true, "description": "Complete 'Tyre Changing' 1 time.", "signatures": [ { "tripId": 12, "signedBy": {"id": 6, "username": "another_verifier"}, "signedDate": "2026-01-25T14:00:00+04:00" } ] } ], "isEligibleForUpgrade": false }

    Create an Upgrade Request¶

    • POST /api/upgraderequests/

      • Creates a new upgrade request.
      • Eligibility Check: Before creation, the system checks if the applicant is eligible for an upgrade based on minimum trips at their current level and required logbook skills for the target level. If the applicant is not eligible, or is already at the highest available level, the request will be rejected with a 400 Bad Request status and a detailed error message listing unmet requirements.
      • Request Body: See the CreateUpgradeRequestSerializer for details. Key fields include:
        • applicant (Member ID of the person being nominated for upgrade)
        • target_level (Level ID)
        • applicant_reason (Text description)
        • nominated_voters (List of Member IDs)

      Note: While the serializer and database use snake_case for field names (e.g., target_level), the API expects camelCase in the request body (e.g., targetLevel).

    Update an Upgrade Request¶

    • PUT or PATCH /api/upgraderequests/{id}/
      • Updates an existing upgrade request. Requires EDIT_UPGRADE_REQ permission.

    Voting and Approval¶

    • POST /api/upgraderequests/{id}/vote

      Note: This endpoint does NOT use a trailing slash.

      • Casts a vote on an upgrade request. Requires VOTE_UPGRADE_REQ permission.
      • Request Body: {"vote": "Y"} (or "N" for No, "D" for Defer)
      • Success Response: {"success": true, "message": "vote_accepted"}
      • Error: Returns upgrade_request_not_open_for_votes if the request status is not NEW or IN_PROGRESS. Returns invalid_vote_choice:<value> for unrecognized vote values.
      • Note: The first vote on a NEW request automatically moves its status to IN_PROGRESS.
      • POST /api/upgraderequests/{id}/approve/
      • Approves an upgrade request. Requires APPROVE_UPGRADE_REQ permission.
      • POST /api/upgraderequests/{id}/decline/
      • Declines an upgrade request. Requires APPROVE_UPGRADE_REQ permission.
      • Request Body: {"verdict_reason": "..."}

    Comments¶

    • GET /api/upgraderequests/{id}/comments/
      • Retrieves all comments for a specific upgrade request.
    • POST /api/upgraderequestcomments/
      • Adds a new comment to an upgrade request. Requires CREATE_COMMENT_UPGRADE_REQ permission.
      • Request Body: {"upgrade_request": <request_id>, "text": "..."}
    • DELETE /api/upgraderequestcomments/{id}/
      • Deletes a comment. Requires DELETE_COMMENT_UPGRADE_REQ permission.

    Recently Approved Requests¶

    • GET /api/upgraderequests/latestapproved

      Note: This endpoint does NOT use a trailing slash.

      • Retrieves a paginated list of recently approved upgrade requests, ordered by verdict date (most recent first).
      • Authentication: Not required (public endpoint).
      • Pagination: Standard pagination (default 20, max 500).

    Voted Requests¶

    • GET /api/upgraderequests/voted

      Note: This endpoint does NOT use a trailing slash.

      • Returns an array of upgrade request IDs that the current user has voted on. Only includes requests with status NEW or IN_PROGRESS.
      • Authentication: Required.
      • Response: A plain array of integers, e.g., [1, 5, 12, 23]

    • GET /api/upgraderequests/{id}/voted

      Note: This endpoint does NOT use a trailing slash.

      • Checks whether the current user has voted on a specific upgrade request.
      • Authentication: Required.
      • Response: json { "success": true, "message": { "voted": true } }
